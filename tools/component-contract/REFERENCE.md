# Component contract: reference

The detail behind [README.md](README.md): what each module does, the contract's shape and how it is held to its spec. Moved here word for word from the README on 2026-11-20.

## What it is

A component's stored spec (`figma.json`) is the drawing, measured: every variant's layer tree, every size and position, every binding. Parity holds code to it, and it is the source of truth. The **component contract** (`contract.json`, beside it) is what that drawing means, said in words no platform owns: the props and their defaults, the anatomy, what each prop value changes, which combinations do not exist. Every value is a token where the design bound one.

It is a layer above the snapshot, never a replacement, and a source only where it is read from code (`from-code.mjs`), in the same shape. A reader that needs intent rather than pixels reads it: code built outside the Figma loop (an MUI library), an agent's brief, a docs page's props table, a version grade on the component's API. ("Contract" here is the component's; `tools/snapshot/projects.cjs` is the routing contract, a different thing.)

## Modules

### `derive.cjs`

`derive(spec)` → the contract; `expand(contract, props)` → the anatomy one combination draws; `selfCheck(spec)` → every stored variant the contract does not rebuild (none, or it is a defect). A placed instance carries its published `key` beside its `component` name (none for a local component), and every reader places it by key first, by name only where the named component's key does not contradict (`layers.mjs` `keyMatches`, `placedOf`): a library may name an icon like a component. An instance's insides are its own component's: with `mains` (`mainsFrom`, and `deriveOptionsFor` in snapshot/projects.cjs, which every writer reads), an instance the walk opened keeps only the layers that differ from its component expanded at its props (its swaps applied, `placedAs`), each layer matched to its part by name (a part a boolean shows, `showIconIcon`, by its layer's name, `asPlaced`) or, renamed in the instance, by its place (`placedMatch`); one that hides a layer of its component, one of another library, or one whose name two components share keeps all it records. So is its own styling: a field it states (layout, corners, fill, stroke, effect, opacity, clipping, smoothing, min and max sizes) equal to its component's root at its props is left out where derive is given `mains` (`ownStyling`; from-code calls it on each combination it reads, as derive on each flat), its size kept as the placement's

### `layers.mjs`

`expand(contract, props)`, `apply` and `variantDefaults`: a combination drawn from the layers, one ES module that `derive.cjs` requires and the contract editor's page imports (served by its `serve.mjs`), so both draw a variant alike; and `interactionStates(settings)` and `statesOf(contract)`, a component's interaction states by one rule, which the editor and the docs site's States table both read

### `write.cjs`

`node tools/component-contract/write.cjs <components dir>` writes every contract beside its spec, for a store whose specs predate contracts or after `derive.cjs` changes

### `test-contract.mjs`

the tests, on a fixture built to hit each case below

### `from-code.mjs`

`node tools/component-contract/from-code.mjs --project <label> <component> [--rebuild] [--code-only | --self | --second]` (`--self`: the toolkit's own rendering instead of the project's code, for eval's self leg; `--second`: the same, rendered from the first self reading instead of the contract, for eval's second leg) (`--rebuild`: a compared library's Storybook built again though nothing it is built from changed): the same contract read from any project the parity engine reads (tools/parity `loadParity`): a library built elsewhere that its context document compares, or a repo whose code follows the design, on whatever host renders it (a Storybook, a site's fragments) through the engine's own session. Props come from what the host declares (a story's controls), or from the mapping's `controls` where it declares none, said as such; a prop that takes content (a docgen's `ReactNode` or snippet, an element the story starts it with, a control stated `slot`) is a slot: a stand-in word is put in it (through Storybook's channel, which takes what its address will not) and the element it lands in is the slot part, `content: "{prop}"`, joined to Figma's slot that fills the same element (Action bar's `children` to Buttons slot); anatomy from the rendered tree, an element a governed mapping places taking Figma's id and the rest named by the markup's part class (`code.partClass`, else the framework's in audit-defaults `frameworks`), a box's own words beside its children a text part of their own; each value matched to the token its field offers (the contract editor's `forField`: Figma's scopes where recorded, else the groups the library's contracts use), with a pair layer wherever two props together do what neither explains, a three-prop layer where three together do what their pairs do not, self-checked by reading every four-prop combination, which built nothing (Chip: every render rebuilt; a first try keyed that three-prop layer to the other props' defaults, and this check found it wrong in every feedback), and every combination of more props the design draws where three or more of its props already build a layer together (`combinationsToRead`, `worthReading`, `readCombinations`: a combination of five props or more whose props build no layer in any three or more of them is predicted from the layers, not read, and the self-check says how many, "N of five props or more left unread"; since 2026-11-21, as the round trip compares every one: Material's square extra-small icon button needs five props off default, its vertical slider five to seven, and both were only predicted before; a reading only in code still stops at four), and compared with Figma's at each combination Figma's grid reads as a layer. Writes `<project home>/parity/from-code/<component>.json`. Then `asFigma()` puts it in the house's Figma conventions (an enum named and valued by its tokens' words, figma-standard rule 22; sentence case, figma-standard rule 18; a swap that can show nothing as a boolean beside its swap, figma-standard rule 5; the axis order the settings derive, `axisOrder`, figma-standard rule 1) and its props are compared with Figma's through the code audit's own `compareProps` (one judgement of a prop, whichever tool asks), with a `structure` list of where the two sides build the same thing differently, which Parity › Visual shows beside what it measured. A trial (2026-10-06, one Chip in 16 s): 29 of 35 values the same token, 2 the same on screen, and 4 icon colours the code audit had skipped (now fixed there); `variant` / `positive` became Feedback / success from the tokens alone, and every prop finding is a real difference (Label text against label, two props only code has, a default the code never declares). Run on three projects' Chips (2026-10-19), a compared library, a governed Storybook and a governed site's fragments: the first unchanged from before, the second all values the same token but its icon (an instance in Figma, one svg in code), the third every value the same. What it cannot recover: which of two tokens holding one value was meant (Feedback and Supportive reds tie), an instance and its swap (the code's icon is one svg), a size a layout resolves, and props a host does not declare (the mapping's `controls` are taken as stated). On a Storybook, a read after the first takes its args through the preview's channel, not a reload (avatar 67 s to 46 s, the same reading), with its CSS transitions run to their end and the walk's marks cleared; a forced pointer state or a slot's stand-in still reloads. Its limit: React keeps the tree, so state a component takes from a prop only at mount (`useState(prop)`, a `defaultOpen`) keeps the last read's value. A value that changes only the glyph drawn is content, so a prop of such values is a swap; where the default shows nothing (an icon left unset), the first glyph says what the swap shows. A slot the story does not draw at its starting props is noted and placed where a read draws it; a mapped layer inside another component's instance is passed over and noted (that component's audit compares it), save one the contract keeps there (an override, which to-markup's mapping names): read under a mapped instance, one level deep, an instance keeping its mapped id (a part a boolean shows is no camel-cased component name), and its own box styling read as a container's, which derive's `ownStyling` folds back where it is its component's root's (2026-11-21; kept only where the winning rule reaches the instance through the component being read, so a holder's override set through a custom property the child reads, in a single-compound or inline rule, or in native CSS nesting is not read yet: before, no instance styling was); a repeated layer and its `#2` each take their own element; a placed component drawn as an icon mark (one the store does not hold) has its stroke, corners and clipping read as its own box's, its outline at focus its own stroke where the design keeps no ring there, as to-code writes it (2026-11-22); a box's four corners are read each (`cornersOf`): four alike one radius, else the list in the order css.mjs writes it, each corner its own token, a square one 0 (before, only the top-left was read, so a split button's [0, M, M, 0] read as no radius; 2026-11-22). `--code-only` reads a component only the code has (a library built elsewhere; its story found by name in their Storybook, `storyIndex`): the same reading from the story's own root, with nothing in Figma to pair or compare it with; the contract editor opens one so. Run on a library built elsewhere (2026-10-23): an avatar group's `max` read as a number prop, its avatars as Avatar instances. Since 2026-10-23 two gaps are narrower: where several tokens hold a value, the one the code wrote it with is named, read from the custom properties its css came through (`authoredVars`: the toolkit's own css name, or a property ending in the token's words), so code that renders through `var()` settles a tie, while code that writes values (an MUI theme) still ties; and a prop's type and whether it is required come from what the docgen read from the source (a number prop, a required one) where the story's control does not say. Since 2026-11-12, for every library, the token the code wrote wins over a guess by the field wherever it holds the value, tie or not (a dot painted with an icon token is not given a palette colour). And for a governed project (its mapping gives each element the design's id), what the code draws the same way is built as the design builds it, so that a drawing from code comes back as the library drew it: a slot holding only words where the design draws a text is that text and the design's string prop; an empty round box where the design draws an ellipse is an ellipse; a radius, gap or padding equal to the design's, or a 0 left unset, takes the design's token; enum values come in the design's order and the component takes the design's name; a mapping's `root` is the root, never a wrapper the story puts around it; and another component found by the project's `parity.instance` is that component's instance. Since 2026-11-13 it takes the rest the design names where it names it once: a word prop under the design's text prop name (children as Label), an enum in the order of a design enum with its words, and under its name where exactly one design enum and one code enum have them (variant as Hierarchy), a swap's boolean and swap under the design's names where a design prop covers that swap alone, an opacity the code writes raw as the single design opacity token holding it, the design's stacking where no child can overlap in any variant, a hugging text's alignment, a box's background layers as the design's fills (rules.mjs `fillsFromCss`, the inverse of to-code's `fillCss`: a linear gradient as its transform, stops and the handles' angle, a colour laid over another as two fills; a layer it cannot read exactly, a stop placed by a length, a repeating or radial gradient, an image, noted and never guessed; Empty state's gradient comes back the same token, 2026-11-14), and a placed component's swap as the first glyph drawn in its own layers that swap drives (none of a copy nested in it), the first the instance draws only where none of those layers is found (on the self leg these layers are found by to-markup's selectors by part id, `byId`, never back through the mapping's paths, which two parts never drawn together share; 2026-11-22); a glyph as the design's icon instance where the design's set holds it and every glyph a variant changes it to (that change becoming a component change); a design name another prop already holds is not taken. A slot on the design's slot layer is the design's slot (its name, settings and preferred instances) and holds the design's sample, as a text prop holds the design's sample words; a wrapper the markup needs and the design does not draw (a list's `li`, one layer at that layer's size, styling nothing) is left out; and another component's instances the markup named by component take the design's ids where the design holds as many of them under the same parent. Context menu went from 30 differences to 8 by the slot alone. The compare keeps what the code wrote. A prop the design has no counterpart for is marked `only: "code"`, the contract editor's own field, and to-figma's `figmaSide` draws its default alone; a code boolean that names one design enum's value (Loading) is folded into it; a code focus outline is read as the design's focus-ring layer (`to-code`'s `ringOf` the other way) its corner the ring's and the box keeping its default corner, the browser's own outline not read; a box centred over its parent is read with centre constraints and drawn there; an instance's props are read from a mapping that names whole combinations (Button 50 differences to 28; what stays is real, such as a ring the design draws on a disabled button and the code does not). The two directions still hold their rules apart (`to-code`/`css.mjs` and this reader); one table of paired rules both read is the next change. Measured on one governed library by drawing each component and reading it back: Badge 17 differences to 1 (its stacking order, which CSS cannot say), Spinner to 1 (an arc). Tested by `test-from-code.mjs`

### `read-cache.mjs`

The self reading's page answers kept (from-code `--self` and `--second`), so a change to how a reading is interpreted (derive.cjs, from-code's node side) re-reads every component without Chrome: carbon's tile, 808 s through Chrome, 29 s from the cache, byte-identical (2026-11-22). Each answer is keyed by the page (every file it is served, Chrome's whole version, each installed font's name, size and date, the system, `LANG`/`LC_ALL`/`TZ`, `cdp.mjs`, the render's own source and how the page is opened, its colour scheme pinned to the tier's by parity's `schemeOf`, never the machine's: a Mac that turned dark at night kept Atlassian's dark tokens, 2026-11-22), the combination's render (its args and forced pointer state), and every question asked since that render, in order, each by its whole text (a page function travels as its source and arguments, so a walker change misses; an element's matched styles by `fetchLevels`' source and the selector). A miss launches Chrome lazily (a reading whose every answer is kept launches none), renders the combination and asks its earlier questions again, each held to its kept answer; one the page no longer gives stops the reading and drops the combination. A CDP send no key can say (node ids) takes the combination live and keeps nothing after it. One gzipped file per combination, matched styles pooled once by content, under the toolkit's common .git beside the measuring lock (`read-cache/`), shared by every worktree and projects root; once a day a run removes what was not read for 14 days (a hit touches it) and pooled parts nothing kept names, and says how much. `TOOLKIT_READ_CACHE=off` reads through Chrome and keeps nothing; `eval.mjs --twice` reads so, holding Chrome's readings to each other. Known limits: two runs writing one combination at once keep the last writer's file (the answers are the same by construction, so only kept answers are lost); a page whose answers vary from run to run fails its replay and must be read again; a partial hit assumes a render resets the page, as the self source's own reuse of a page already does; a change to one component's markup or sheet misses that component and every one that places it (the page holds only that closure), and a token change misses only the components whose sheets reach it. Tested by `test-read-cache.mjs`

### `rules.mjs`

The translation table between the contract and both sides, one row per rule, read in every direction: `derive.cjs` (Figma → contract), `css.mjs` (contract → CSS), `to-figma.mjs` (contract → Figma, handed to the plugin as data) and `from-code.mjs` (CSS → contract). Since 2026-11-13 it holds alignment (`ALIGN_ROWS`: the contract's word, Figma's, CSS's; Figma has no stretch, said lossy) and sizing (`SIZE_ROWS`, `sizeFromCss`, `layoutFromCss`). Code is read from its authored declarations, the element's and its parent's as the cascade chose them, never from a measured box (CSSOM gives a width as used pixels, so hug and fill are lost there): flex-grow and a fixed basis along the flow, stretch across it, a grid item stretched both ways, an outer box filling a story's frame as that frame's width, a root that fills as Figma's root fill with its room as `canvas`. Measured on every stored contract of four projects: 60,565 of 60,624 sizes and 3,259 of 3,262 layouts come back through contract → CSS → contract, and every alignment and size through contract → Figma → contract; on nine governed components read from their code, 93 of 98 sizes equal Figma's, the rest what the code writes (a hand-written stretch, a `flex: 1`). A gap below 0, which CSS cannot say (a negative `gap` is invalid), has a synonym: each child after the first pulls back by a negative start margin, said by every child of such a box on its own rule in every combination (the gap after the first in the flow; 0 for the first, a placed part, and where a variant's gap is not below 0), never left to an unset; copies of one part and a slot's children share a rule, so between them it is said as unread (`negative`, `pullProp`; `layoutFromCss(own, next)` reads it back, from-code taking it only where it renders below 0). A wrapped row pulls the first item of each line too, and a negative token is known by its name (`Spacing/-1`). Placement (`placeFromCss`): absolute (fixed is the viewport's, left to from-code's walk), an edge's inset pins it there, both edges stretch it (unless it sets its own size, when the far inset gives way), an inset of 50% shifted back by half (translate, translateX/Y, translate3d) centres it; offsets kept as written. Figma's scale constraint has no CSS word, so its synonym is a share of the parent (`share`): offset and size as percentages where the parent's size is a number, read back as scale; 2,746 of 2,759 stored placements come back the same, the 13 others sit in a parent with no numeric size. A centre the declarations do not say (auto margins) is taken from the measured box. Text: how a text resizes is its sizes (`autoResizeOf`: width hugs → `width_and_height`, height hugs → `height`, else `none`; held on 1,521 of 1,521 stored texts), its cut is `linesFromCss` (an ellipsis on one line, a clamp to N), and its style is named by the declarations that say it (`styleFromCss`, every field as to-code writes it matching), from-code falling back to the values where none does. A text that hugs its width never wraps in Figma, where CSS would wrap it at the room it has: css.mjs says it with `white-space: nowrap`. A root that fills its container is read in a room as wide as the library draws the component (a ruling: a Figma component's own frame has no parent to fill), measured at the width it renders there, and `roundTrip` compares a root filling a room as that room's width. Fills are here both ways (`fillCss`, `fillsFromCss`). Strokes, corners, shadows and states are still written in css.mjs and read by from-code's own walk; moving every rule into paired rows here is the work under way (2026-11-14), so a writer can no longer say what its reader cannot read. Tested by `test-rules.mjs`

### `test-battery.mjs`

The battery: one made-up contract holding a case for each cell of `rules.mjs`'s sizing, alignment, placement and text (not yet its fills) (sizing: direction × the box's size × the child's along and across; alignment; every constraint pair in a frame and in an auto layout; an empty box, a negative gap, wrap, min/max, padding per side), sent round each path and held to itself by value. `node tools/component-contract/test-battery.mjs` runs contract → `to-code`'s CSS → Chrome → the authored reader and the table → contract (in `bin/check`; a skip without Chrome); `--figma <scratch fileKey> --project <label>` also runs contract → `to-figma` → the file → the snapshot's walk and `derive` → contract. Abstracted from components: a cell that fails here fails in every component that has it. Each case names the capabilities it holds, and each run ends with the coverage: of `capabilities.json`'s capabilities, those every case holding them brought back the same, per family.

### `capabilities.json`

What Figma and CSS can each say for a component, one row per capability (family, Figma's property, CSS's, whether they are the same, a synonym, or one side's only, and the page read for it): Figma's plugin API reference and MDN, 2026-11-13; a row whose CSS side no MDN page was read for says "CSS side unverified" in its note. Coverage is reported over every row and over those both sides can say (same or a synonym), which is what a round trip can hold. The universe `test-battery.mjs` measures its coverage against

### `to-figma.mjs`

`node tools/component-contract/to-figma.mjs <from-code report> <keys.json>` prints plugin code (run through the Desktop Bridge) that draws the contract as a component set: an enum, or a boolean that restyles, is a variant axis; a boolean that only shows layers is a boolean bound to their visibility (all a Figma boolean can do); every value bound to the library variable, text style or Icon container the contract names. When the scratch file is the library's own file (`--into` equals the library's key), a key the file holds is taken from it, so that file need not be published; every other key is imported from the published library. There each drawing goes on a page named `Round trip · <component>`, never on the library's own page of that name, and a snapshot of the file drops every component and frame on such a page (`payload.cjs` `drawnPage`, the prefix to-figma draws with). A text style, icon or variable another library lent the file is taken from the copy the library's own component of that name uses, since a copy of a community file reaches none of the libraries it was made with; a copied text style that withholds its font is drawn in the font of a text using it. There, a variable the library's own component binds is taken by name from that binding, over the snapshot's key, which can name another variable of that name (two collections of one name) and, hidden from publishing, one no import reaches; a mode's collection whose every variable is hidden is reached the same way (2026-11-24). A layer the library paints with a colour style keeps it in the contract beside its colour (`fillStyle`), and the drawing sets that style by its key once the layer is painted, only where the style's colour as the snapshot records it is the part's (an edited colour is drawn as itself and said; the contract editor clears the style when a colour is edited), the key looked up where the library uses it (the snapshot records no colour style's key); code has no styles, so a reading from code is never held to one (2026-11-23). A value is a variable where it has a group or the project's tokens name it (a variable at the top of its collection), and a text no style names is drawn in its values' face, size and line height. On this leg alone, a library's 0 size reads as Figma's 0.01 minimum, and a bare `literal` (no single face recorded) as any drawn literal. `--run --project <label> --into <scratch fileKey>` draws it through the project's docs service (its `/exec`), on a page of the component's own name in the scratch file (a new page put after the last whose name comes before it, so a file kept in alphabetical order stays so; the drawing at 0,0; each variant at the place the library's stored figma.json records for it in its set and the set at the size it records (snapshot 0.84.0 on, `arrangementOf`: a drawing fact read at draw time, not a contract one, since code has no set to place), where that spec places every variant drawn; else, as for a contract from the editor, a set laid out by grid auto layout 24 apart and 24 in, a row per combination of its axes but the last and a column per value of the last, a combination not drawn left an empty cell; where Figma refuses grid layout the same grid is laid out by hand and the run says so; a component of one variant never a set; one run at a time in the file, asked before any page is touched), replacing this component's last drawing there, keeping one an instance still uses, and refusing a page holding anything else (a page of that name someone made by hand included). Drawings made before 2026-10-20 sit on one "From code" page and are not read: delete that page once its components are drawn again; text-style keys come from the snapshot (plugin 0.51.0 on), the rest are looked up by name where the library uses them. Without `--run`, `<keys.json>` names the keys and the plugin code is printed. A trial (2026-10-06): Chip, 20 variants on a scratch file, every value bound, 24 px as the code draws it. A part the code draws as another library component (a chip's avatar, found by its framework's root class, the profile's `instance` in audit-defaults `frameworks`, or a governed project's `parity.instance`) is drawn as that component's instance, at the variant its contract's `with` names (from-code reads it from the instance's markup: each axis of that component's mapping at the value whose args the markup carries, its icons by `data-icon`; since 2026-11-14 its words, the props that put words in its texts one for one (`wordsOf`, a word passed down from this component's own prop said as `{prop}`), and each boolean that shows a layer, true where that layer's selector in its own mapping is drawn). A stroke on some sides, which css.mjs writes as one offset ring per side, reads back per side (parity's `sideStrokes`), as does a CSS border whose sides differ; an effect style the code lists as one layer among others (`inset 0 0 0 1px var(--stroke), var(--elevation-raised)`) is read as that style (`layerVars`), and a ring all round inside the style is the style's, not a border, its other props set after, and said to be compared in that component's own audit. `--verify` reads the drawing back out of Figma (each variant's layers and the variables, text style and component each is bound to) and holds it to the contract it was drawn from, its rows in `<report>.drawn.json` beside the report (written only when they changed, so a run that finds what the last one did changes no file): with `from-code.mjs` holding the code's contract to Figma's, all three sides are compared (Chip 134 the same, Switch 26, 0 different in either; what is not bound waits on the snapshot's variable keys). Since 2026-11-12 it also holds the drawing to the library's own component of that name, where the library has one: the drawn set read by the snapshot plugin's own walk, derived as the snapshot derives it, and every combination the library draws (its enums and booleans, every one since 2026-11-14, none it marks `invalid`) expanded from both contracts and compared field by field (`roundTrip`), so a contract's wording (its default, the order of its values) does not count and what a variant draws does; its rows in `<report>.roundtrip.json`, a difference failing the run; `--library <contract> --folder <component folder>` holds it to that contract instead of the folder's contract.json (eval.mjs passes the official one). Bindings alone had passed a Badge whose label was an empty 100 px slot. Before that, it held bindings, not geometry: a first Switch passed it with its thumb drawn apart from its track, which `from-code` now records (a part code places absolutely, a box's set width and height) and the drawing places (absolute layers on top, an empty box at its size). With Figma behind other windows its calls answer in slow ticks: a Chip draws in about 10 s in front, minutes behind. A derived contract is drawn back as the library drew it: its name and its options' spelling; a boolean a property unless the contract marks it `axis` or a layer of its own restyles; each slot with its settings, description and preferred instances; each instance swap property linked to the instances that are its; an instance at its own size, its inner layers found by name (by place where a swap renamed one, and again where setting a sibling's props rebuilt them) and given the contract's values, sizing included, as overrides; a gradient as one, an image fill said rather than painted; a variant that fills its set in a track fixed at the width the set gave it (the contract's `canvas`), else at the most its variants draw at; rectangles, ellipses, lines and turned layers as such; layers in their order. Held to it on 2026-10-20 by drawing all 63 components of one library and reading each back with the snapshot plugin, field by field. What still differs is said: a private component (`_Label`) cannot be imported, so a frame stands in; the description is left out (above); the variants follow the house's axis order (figma-standard rule 1); a component drawn on its own page carries its full name; a picture's image is not in the contract; and, until the library is snapshot again with plugin 0.62.0, a focus ring's stretch, a text's per-variant words, and arcs. `--patch <set id> --project <label> --into <fileKey>` updates an existing component set in place (the contract editor's *Update the library component*): the contract drawn as for a new one beside it, then copied onto the set node by node and the drawing removed; a version is saved in the file's history first. The set and each variant that stays keep their node and key, so instances stay linked; a layer matched by name (and number) keeps its node, so an instance's override on it stays; properties are added, removed and given their defaults by name; a variant matched by its values, one no longer drawn removed (its instances in the file counted), a new one placed in the library's own layout; a renamed option is a removed variant and a new one; a renamed, added or removed axis is refused before anything changes (a variant moved into a set takes the set's axes, so it would not take); a new slot is added, one property across the variants with the drawing's settings (tested on a scratch set, 2026-10-26), and a slot is never removed; a size is copied only on an axis that is fixed, so one that hugs or fills keeps doing so. `--base <contract>` refuses, before anything changes, where the set read live (the snapshot plugin's own walk, headless, its contract derived as the snapshot derives it) is no longer that contract; refused too where the drawing could not draw something as the contract says (a value it could not bind would be copied raw over the library's binding) or ran past 300 s (its caller may have stopped waiting), and said where the snapshot is older than the toolkit's contracts (take one, then open the component again). A trial (2026-10-30): one project's 63 components, generated into a copy for both frameworks, type-check under its `tsc` and lint clean under its ESLint (126 files), and with its generated sheets and tokens draw every part where the contract does and styled as it draws it at all 1534 combinations in Chrome; every control its web components draw at their defaults has a name. A second (2026-10-30): one Kirby project's 41 stored components, generated into a copy as snippets, parse under `php -l`, render under PHP with every notice fatal at all 242 combinations, and each is its web component's tree, element, attribute and word. Tested by `test-to-markup.mjs`, which does the same in Chrome for the sample library's web components, renders each Kirby snippet through PHP and holds it to its web component's tree at every combination, holds the React text to the knowledge pages, and breaks a contract on purpose (code in its words, a text entry) A box's children come in the order every variant states (a part a variant adds takes the place it gives it); where two variants disagree the base order stands. A swap of one of the library's components (an instance swap property over a placed component the library holds: Atlassian's button group's `<Button> 1`, Carbon's Swap slot) is content the caller passes, drawn where given, and the design's own instance at its values where not, in each layer the swap drives and as a variant swaps that instance for another of the library's, so the code draws what Figma draws at the swap's default (since 2026-11-21; a snippet keeps the slot); from-code reads a slot the self leg's story marks `placed` (`selfSlotControl`; a real Storybook's docgen default is no such mark and keeps the stand-in) at that default, with no stand-in, and takes the design's swap of that key where the reading draws each layer it swaps as an instance (`asDesignSwaps`), else a slot.

### `official.mjs`

Which contract is a component's official one: Figma's reading beside the spec (`contract.json`), or, where the library's audit settings say `"source": "contract"`, the project's own file, `<home>/contracts/<component key>.json`, which no snapshot writes and a rename in Figma does not lose. `officials(where).of(c)` and `contracts(where)` are what to-code, from-code, the code audit, the contract editor, the docs site and the evals read; `behind(where)` is where Figma's reading differs (`changed`, `new`, `gone`), `figmaBrief` says it for the designer. `node tools/component-contract/official.mjs --project <label>` lists it; `--switch contract` makes the contracts as they stand official and sets the setting; `--switch figma` lists what Figma is behind on and, with `--confirm`, drops the files and the setting. The look parity measures stays the snapshot's in either mode. Tested by `test-official.mjs`

### `css.mjs`

`declarations(part, at, names)`: a contract part's fields as CSS declarations, the one translation from the contract's words to CSS (figma-handoff's mapping; code-standard rules 22, 54 and 63), naming values through what it is given (to-code: the token build's custom properties); what CSS cannot say returned in `unread`. An image fill is the project's: the sheet writes it as `var(--image, <a clear pixel>)`, sized as Figma fits it (FIT contain, FILL and CROP cover, TILE repeated), and the project sets `--image: url(…)` on the component; a value that is not an image voids the whole background, its colour included, and CROP reads back as FILL.

### `contract-rows.mjs`

`rowsOf` and `propsOf`: a component's properties table read from its contract; `node tools/component-contract/contract-rows.mjs <components folder> [component…]` prints each component's rows as JSON; with `--live <project> <page…> [--file <library key>]` (the key naming the library where the project routes several) it asks the project's audit service (`/table-rows`) to run the snapshot plugin's walk on the open file and prints the `PT.rows({…})` call figma-properties-table draws from (`rowsFromWalk`: each component recorded as the store records it, `store.cjs` `recordOf`). The docs site reads `propsOf`, in `rowsOf`'s order. Tested by `test-contract-rows.mjs`

### `analyze.mjs`

`consistency(components)`: a library against itself, by form — one prop as a variant here and a boolean there, one name spelled two ways, one prop numeric here and named there. Filed by the docs service into figma-components-audit's queue under the target `consistency` whenever the snapshot moves. Tested by `test-analyze.mjs`

## How the contract is held to its spec

The router writes the contract beside every spec on each library snapshot (`store.cjs`), and `check-specs.cjs` holds it to what the spec derives and to rebuilding every variant: a project's `bin/check` through `tools/project-check/check.mjs`, the toolkit's own `bin/check` for a design-only project's stored specs.

## The shape (contract 1)

    { "contract": 1, "component": "Button", "figma": { "name", "key", "id" },
      "props":   { "size": { "type": "enum", "values": ["large", "small"], "default": "large", "figma": "Size" },
                   "leftIcon": { "type": "boolean", "default": false, "figma": "Left icon", "shows": ["content/leftIconIconContainer"] },
                   "labelText": { "type": "string", "figma": "Label text", "sets": ["content/label"] },
                   "state": { "type": "enum", …, "role": "interaction", "pointer": ["focus", "hover", "press"] } },
      "anatomy": { "root": {…},
                   "content": { "kind": "container", "parent": "root", "order": 0, "layout": { "direction": "row", "gap": "Spacing/4", "padding": { "top", "end", "bottom", "start" }, "align", "crossAlign" }, "width": "hug", … },
                   "content/label": { "kind": "text", "parent": "content", "order": 0, "typography": "Label/md", "color": "Text/inverse", "content": "{labelText}" } },
      "variants": [ { "when": { "size": "small" }, "set": { "content/label.typography": "Label/sm", … } },
                    { "when": { "leftIcon": true }, "add": { "content/leftIconIconContainer": {…} }, "set": { "content/label.order": 1 } },
                    { "when": { …every prop… }, "set": {…}, "combination": true } ],
      "invalid": [ { "size": "large", "disabled": true, "state": "hover" } ],
      "when":    { "spinner": { "state": ["loading"] } } }

- **Props.** A False/True variant axis is a boolean, marked `axis: true` (a boolean property is not). An enum keeps Figma's spelling of its options in `figmaValues` (`Primary`, `Icon only`, `lg`), which the kebab-case `values` lose or the house's sentence case would change; a False/True axis keeps its two options there too where Figma's order or spelling is not `False`, `True` (`true`, `false`), which the drawing names its variants by. A boolean's default is the side its walked trees were not flipped to; an enum's is the value of Figma's default variant (recorded by the plugin from 0.50.1; the first variant before); a text property's is the words its layer holds in that variant, and is never a key a variant is chosen by. The State axis is figma-standard rule 4's: `pointer` lists the Focus, Hover and Press it has; Rest is none, Loading is a prop in code (figma-standard rule 58), and any other value is the component's own.
- **Modes.** A layer that sets a variable collection's mode in Figma carries `modes: { <axis>: <mode> }`, keyed as the token build writes the attribute (`tools/tokens/modes.cjs`: `theme` for Light/Dark, else the axis's first collection's slug), from the axes of the project's tokens file; a variant that sets another sets `<id>.modes`. to-figma sets it on every collection of the axis, to-markup writes `data-<axis>`, from-code reads it back. A collection the tokens file does not hold keys under its own slug, and the drawing says it cannot set it.
- **Empty frames.** A slot that hugs and holds nothing, or the empty sample frame a slot holds, keeps the size Figma left it at, and only while empty: `minHeight` (or `minWidth`) with `whileEmpty: ["minHeight"]`, never where a variant fills it. to-code writes it for the empty box alone (`:not(:has(*))`, so a box holding only text counts as empty: a limit), unsets it where the design fills it, from-code reads a minimum written there back as `whileEmpty`, and to-figma draws the empty frame at that size, hugging (a Dialog's content 172 empty, 146 on a screen that fills it).
- **What a prop drives.** `shows`: the layers a boolean adds, found by aligning its walked tree with the variant it was flipped from (not by name: a left and a right icon share one), or, for a boolean on by default, the layers its flip hides. `sets` and `swaps`: from the links the snapshot plugin records (0.50.0 on, addressed as the anatomy is from 0.50.1); a snapshot from before says nothing rather than guess. A link that holds in some variants only (0.61.0 on) is said there: an instance names the swap that is its at those values (`swappedBy`, a set giving each size its own icon swap on one layer), and a text keeps its own words where its property does not drive it. Of two same-named layers, the one a boolean hides is the one that is not the same layer in its flipped tree (its component, props and words). A boolean only shows and hides this component's own layers: a layer its flipped tree shares with the variant keeps that variant's fields but for its place (a flip is walked from a detached copy, whose sizes are its own), and what differs inside a placed instance is that instance walked otherwise, not the boolean's.
- **Anatomy.** One flat map of elements. An id is the layer's address in camel case, `/` between levels, a repeated name numbered past a separator (`label_2`, so it never meets a layer named "Label 2", which is `label2`), a boolean's own layer named for its prop: it depends on nothing but the layer's own path, so a layer added elsewhere renames nothing. `order` is the place among its siblings, so an axis that only moves a layer is a change. Two layers two booleans show, both hidden by default, are each walked alone at the same place, a tie; where the snapshot says each layer's place among all its parent's children (`index`, 0.83.0 on), the booleans that would tie take it as their box's children's `order`, so the two come in the order Figma draws them (an older snapshot's contract, and one no tie touches, stay as they were; to-figma leaves `index` out of a live read held to a snapshot without it). Position and the size a hug or fill resolves to are drawing, not intent, and stay in the snapshot.
- **Variants as layers,** read the way a grid is read: what one prop value changes with every other prop at its default, then what a pair adds on top, then a trio; what is left (more than three props off their defaults) is per combination. `expand` applies the default, every layer whose props all match, then the combination; a part goes with its parent, so one a layer adds inside a part another removes is not drawn.
- **Invalid.** The variant-axis combinations the grid does not draw, a prop left out of every entry when, in each, none of its values is drawn with the other props alike (out of all entries or none; a key left out is any value); `null` where there are too many to list (over 4,096), which is not "all valid".
- **When.** A part drawn only under some props' values, keyed by the part's id: `{ "dot": { "size": ["large"] } }`. Read off every drawn variant and written only where exact, the part drawn if and only if the condition holds. A boolean is never in the condition of its own layers (its `shows` says that), though they may carry one on other props (a chevron drawn only in some states). Not written for a layer inside a placed component (that component's) or a part drawn exactly where its parent is, and naming only the props it needs: a prop whose other values the grid never draws with the part is the invalid list's to say. Figma has no conditional property; code does (a union type), and Curtis, Trueman and Southleft's prototype all put the condition on the part. `invalid` stays what Figma did not draw, a canvas fact, not a type rule for code.
- **Shape.** A layer Figma draws as an ellipse or a rectangle carries `shape` (`ellipse`, `rectangle`), part of a circle or a ring its `arc` (degrees, snapshot 0.62.0 on; drawn in code as a conic mask, a hollow one cut by a radial, and read back from it), a vector its `paths` (Figma's own, snapshot 0.86.0 on; to-figma draws them, code draws the box and says `paths` unread; none for a line along a box of no height or width where to-figma draws it as its line, which the box and its stroke draw: spec.cjs `boxOnly`; a closed box path keeps them, its fill rule being more than the box), and a turned one its `rotation`; a border its `cap` where its ends are not square; a box's corners say the rest.
- **Names.** A part carries `name`, Figma's own, only where its id cannot say it back (a repeat beyond the first, a layer a boolean shows, a name camel case mangles); otherwise its name is its id's last part in words (`layers.mjs` `partName`, which every reader uses).
- **What a drawing needs beyond tokens.** A token bound at 0 is said (a `Corner radius/0`); a radius per corner and a stroke width per side are lists, a bound side by its token beside the others' numbers; a stroke weight bound where no stroke is painted is kept (a border with no colour); a border says `align` (`center`, `outside`) and `inLayout` where Figma's are not inside and out of the layout, and `dash` (drawn in code as a dashed outline whose length the browser picks, so compared as dashed or not); wrapped rows their `crossGap`; a box stacked first on top `firstOnTop` (snapshot 0.62.0 on); a component that fills its set the size the set gives it (`canvas: { width }`), a canvas fact as `invalid` is; an `opacity` its token; `blend`, `mask`, `smoothing` where set; a part in a box with no auto layout, or placed out of the flow, its point (`absolute: { x, y }`) and how it follows its parent's size (`constraints`, snapshot 0.61.0 on), and where it follows its parent's end or bottom, how far from it (`end`, `bottom`, as CSS's `right` and `bottom`); centred, both edges, so its centre's distance from the parent's is (x − end) / 2 whatever size code renders either box at, drawn as `calc(50% ± d)` and compared as that distance (to-figma `pinned`) where both sides say both edges (limits: an offset that is a token draws dead centre, and a hand edit to x alone is overridden by the stale far edge): stretched, it has no `width` or `height` of its own, the parent's less both offsets (a focus ring measured at one label's width, 89, was drawn 89 round a chip that had grown to 290); text its `autoResize` and `verticalAlign`, and, where no text style sets them and the snapshot records its size (0.82.0 on), its letter spacing, case and decoration, and its own values as its `typography`, `literal size/lineHeight weight[ italic] family` in px as code reads them (rules.mjs `typeValue`; a family that is a CSS keyword bare, and one of the seven Chrome quotes back quoted where a font is called so; an older snapshot's, and a `mixed` text's, the word alone and none of those fields, so a stored contract stays as it is; one whose face the weight table has no name for, Display Bold, or whose line heights are several, the word alone beside those fields, so its size is not carried), which css.mjs writes as plain values, with `normal` or `none` for the slant, spacing and case it leaves out, as those inherit, and the reason `no text style in the design`, since the snapshot records no variable bound to them; from-code reads a text matched to a style by size, line height and weight as that style alone, and any other with its spacing, case and decoration (an ancestor's underline too, where CSS draws it on the text), whatever the design says of that layer (to-figma draws the spacing, case and decoration, not yet the literal's size and face: it handles one as it does `literal`, said and not bound to a style, so an update in place that would draw one is refused as it is for `literal`; its live read held to a stored figma.json that records no such size says `literal` as stored, `walkedAs`, so the same library is no change). A slot part links its prop as text does (`content: "{prop}"`), and a slot prop keeps its `description`. Each was found missing by drawing contracts back into Figma and comparing the snapshot plugin's reading of the drawing with the original's, field by field.
- **Left out:** the description (guidance, as Curtis and Pitre both leave it), pixels where a token exists, and anything a stored spec does not hold (motion, behaviour, accessibility). An instance's inside is walked as drawn; which of it is the instance's own and which an override is not yet told apart.

On every component stored on 2026-10-05 — 419, across four projects — every variant rebuilt exactly, the contracts are 12% of the specs' size, and deriving all of them took under a second.
