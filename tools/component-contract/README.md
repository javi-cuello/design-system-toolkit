# Component contract

A component's stored spec (`figma.json`) is the drawing, measured: every variant's layer tree, every size and position, every binding. Parity holds code to it, and it is the source of truth. The **component contract** (`contract.json`, beside it) is what that drawing means, said in words no platform owns: the props and their defaults, the anatomy, what each prop value changes, which combinations do not exist. Every value is a token where the design bound one.

It is a layer above the snapshot, never a replacement, and a source only where it is read from code (`from-code.mjs`), in the same shape. A reader that needs intent rather than pixels reads it: code built outside the Figma loop (an MUI library), an agent's brief, a docs page's props table, a version grade on the component's API. ("Contract" here is the component's; `tools/snapshot/projects.cjs` is the routing contract, a different thing.)

## The shape (contract 1)

    { "contract": 1, "component": "Button", "figma": { "name", "key", "id" },
      "props":   { "size": { "type": "enum", "values": ["large", "small"], "default": "large", "figma": "Size" },
                   "leftIcon": { "type": "boolean", "default": false, "figma": "Left icon", "shows": ["content/leftIconIconContainer"] },
                   "labelText": { "type": "string", "figma": "Label text", "sets": ["content/label"] },
                   "state": { "type": "enum", …, "role": "interaction", "pointer": ["focus", "hover", "press"] } },
      "anatomy": { "root": {…},
                   "content": { "kind": "container", "parent": "root", "order": 0, "layout": { "direction": "row", "gap": "Spacing/4", "padding": { "top", "end", "bottom", "start" }, "align", "crossAlign" }, "width": "hug", … },
                   "content/label": { "kind": "text", "parent": "content", "order": 0, "typography": "Label/md", "color": "Text/inverse", "content": "{labelText}" } },
      "variants": [ { "when": { "size": "small" }, "set": { "content/label.typography": "Label/sm", … } },
                    { "when": { "leftIcon": true }, "add": { "content/leftIconIconContainer": {…} }, "set": { "content/label.order": 1 } },
                    { "when": { …every prop… }, "set": {…}, "combination": true } ],
      "invalid": [ { "size": "large", "disabled": true, "state": "hover" } ],
      "when":    { "spinner": { "state": ["loading"] } } }

- **Props.** A False/True variant axis is a boolean, marked `axis: true` (a boolean property is not). An enum keeps Figma's spelling of its options in `figmaValues` (`Primary`, `Icon only`, `lg`), which the kebab-case `values` lose or the house's sentence case would change. A boolean's default is the side its walked trees were not flipped to; an enum's is the value of Figma's default variant (recorded by the plugin from 0.50.1; the first variant before); a text property's is the words its layer holds in that variant, and is never a key a variant is chosen by. The State axis is figma-standard rule 4's: `pointer` lists the Focus, Hover and Press it has; Rest is none, Loading is a prop in code (that rule's note), and any other value is the component's own.
- **What a prop drives.** `shows`: the layers a boolean adds, found by aligning its walked tree with the variant it was flipped from (not by name: a left and a right icon share one), or, for a boolean on by default, the layers its flip hides. `sets` and `swaps`: from the links the snapshot plugin records (0.50.0 on, addressed as the anatomy is from 0.50.1); a snapshot from before says nothing rather than guess. A link that holds in some variants only (0.61.0 on) is said there: an instance names the swap that is its at those values (`swappedBy`, a set giving each size its own icon swap on one layer), and a text keeps its own words where its property does not drive it. Of two same-named layers, the one a boolean hides is the one that is not the same layer in its flipped tree (its component, props and words). A boolean only shows and hides this component's own layers: a layer its flipped tree shares with the variant keeps that variant's fields but for its place (a flip is walked from a detached copy, whose sizes are its own), and what differs inside a placed instance is that instance walked otherwise, not the boolean's.
- **Anatomy.** One flat map of elements. An id is the layer's address in camel case, `/` between levels, a repeated name numbered past a separator (`label_2`, so it never meets a layer named "Label 2", which is `label2`), a boolean's own layer named for its prop: it depends on nothing but the layer's own path, so a layer added elsewhere renames nothing. `order` is the place among its siblings, so an axis that only moves a layer is a change. Position and the size a hug or fill resolves to are drawing, not intent, and stay in the snapshot.
- **Variants as layers,** read the way a grid is read: what one prop value changes with every other prop at its default, then what a pair adds on top, then a trio; what is left (more than three props off their defaults) is per combination. `expand` applies the default, every layer whose props all match, then the combination; a part goes with its parent, so one a layer adds inside a part another removes is not drawn.
- **Invalid.** The variant-axis combinations the grid does not draw, a prop left out of every entry when, in each, none of its values is drawn with the other props alike (out of all entries or none; a key left out is any value); `null` where there are too many to list (over 4,096), which is not "all valid".
- **When.** A part drawn only under some props' values, keyed by the part's id: `{ "dot": { "size": ["large"] } }`. Read off every drawn variant and written only where exact, the part drawn if and only if the condition holds. A boolean is never in the condition of its own layers (its `shows` says that), though they may carry one on other props (a chevron drawn only in some states). Not written for a layer inside a placed component (that component's) or a part drawn exactly where its parent is, and naming only the props it needs: a prop whose other values the grid never draws with the part is the invalid list's to say. Figma has no conditional property; code does (a union type), and Curtis, Trueman and Southleft's prototype all put the condition on the part. `invalid` stays what Figma did not draw, a canvas fact, not a type rule for code.
- **Shape.** A layer Figma draws as an ellipse or a rectangle carries `shape` (`ellipse`, `rectangle`), part of a circle or a ring its `arc` (degrees, snapshot 0.62.0 on), and a turned one its `rotation`; a border its `cap` where its ends are not square; a box's corners say the rest.
- **Names.** A part carries `name`, Figma's own, only where its id cannot say it back (a repeat beyond the first, a layer a boolean shows, a name camel case mangles); otherwise its name is its id's last part in words (`layers.mjs` `partName`, which every reader uses).
- **What a drawing needs beyond tokens.** A token bound at 0 is said (a `Corner radius/0`); a radius per corner and a stroke width per side are lists, a bound side by its token beside the others' numbers; a stroke weight bound where no stroke is painted is kept (a border with no colour); a border says `align` (`center`, `outside`) and `inLayout` where Figma's are not inside and out of the layout, and `dash`; wrapped rows their `crossGap`; a box stacked first on top `firstOnTop` (snapshot 0.62.0 on); a component that fills its set the size the set gives it (`canvas: { width }`), a canvas fact as `invalid` is; an `opacity` its token; `blend`, `mask`, `smoothing` where set; a part in a box with no auto layout, or placed out of the flow, its point (`absolute: { x, y }`) and how it follows its parent's size (`constraints`, snapshot 0.61.0 on), and where it follows its parent's end or bottom, how far from it (`end`, `bottom`, as CSS's `right` and `bottom`): stretched, it has no `width` or `height` of its own, the parent's less both offsets (a focus ring measured at one label's width, 89, was drawn 89 round a chip that had grown to 290); text its `autoResize` and `verticalAlign`, and, where no text style sets them, its spacing, case and decoration. A slot part links its prop as text does (`content: "{prop}"`), and a slot prop keeps its `description`. Each was found missing by drawing contracts back into Figma and comparing the snapshot plugin's reading of the drawing with the original's, field by field.
- **Left out:** the description (guidance, as Curtis and Pitre both leave it), pixels where a token exists, and anything a stored spec does not hold (motion, behaviour, accessibility). An instance's inside is walked as drawn; which of it is the instance's own and which an override is not yet told apart.

On every component stored on 2026-10-05 — 419, across four projects — every variant rebuilt exactly, the contracts are 12% of the specs' size, and deriving all of them took under a second.
