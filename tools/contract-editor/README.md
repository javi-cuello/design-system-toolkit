# Contract editor

A page for writing a component's contract before anyone draws or builds it: designers and engineers add its props and parts as blocks and leave with the contract as JSON. The contract is the one [component-contract](../component-contract/README.md) derives from a finished drawing, written the other way round: intent first. It also opens a library's stored contracts, and writes them back with nothing lost.

**Who owns what.** For a component Figma has drawn, the stored contract is still derived from the snapshot on every snapshot (`bin/check` holds it to that), so the record is Figma's. The editor is where a change to its API (props, parts, conditions, combinations) is written and proposed for review; the proposal is made in Figma and code, and the next snapshot derives it. It opens to be read, as Figma's Dev Mode shows a component: no palette, nothing to drag, add, move, delete or rename, its JSON not to edit, each prop and each part opening to a label and its value a row, as text, and the Figma menu offering Pull alone, as there is nothing to propose. **Edit as draft** makes a draft linked to it (below) and keeps it in this browser's drafts and makes the page the draft's to change; in the draft its look is editable too, as it is the user's copy: Push as new draws it as its own component, and Update the library component, behind a confirm, rewrites the component in the library file itself (`to-figma --patch`, below). A new component, and a part added here, have their look set here, as a seed for Figma.

## Quick start

You need Node 22.12 or later, the Figma desktop app, and a Figma library file. None of the toolkit's projects is needed.

1. Clone the toolkit, or only the editor and what it uses: `git clone --filter=blob:none --sparse https://github.com/javi-cuello/design-system-toolkit.git toolkit && cd toolkit && git sparse-checkout set --cone bin && bin/get tools/contract-editor` (the snapshot plugin comes with it). In Figma, **Plugins › Development › Import plugin from manifest…** and pick `plugins/design-system-snapshot/manifest.json`.
2. Run `node tools/contract-editor/serve.mjs` and open http://localhost:9250/. It starts the snapshot router too, unless one is running (a login agent from `install.sh`, restarted after an update: `launchctl kickstart -k gui/$(id -u)/com.toolkit.figma-snapshot`).
3. Run **Design system snapshot** in your library. No project claims it yet, so the router keeps the snapshot and the plugin shows a code. In the editor's **Settings**, give the project a name, paste the library's address and type the code. The project is made, and the kept snapshot goes into it.

Optional: in **Settings**, name a local git repo as the code repo, then its styles folder and framework. **Push to code** then writes a new component's stylesheet there, and its component, parity mapping and story.

**Push to Figma** also needs a scratch file, and the Desktop Bridge (Figma's, not the toolkit's) open in it.

## Use

```sh
node tools/contract-editor/serve.mjs --project <label>     # http://localhost:9250/ (or its editorPort), that project's library and no other
node tools/contract-editor/serve.mjs --snapshot <dir>      # any snapshot folder, or a repo with a snapshot.config.json
node tools/contract-editor/serve.mjs                       # house settings, no library, no tokens; Settings makes a project
```

**Started on no project,** the editor starts the snapshot router too (where nothing holds its port; `--no-router` leaves it out), and Settings offers **Create a project**. Where the router kept the snapshot of a library no project claims, it asks a name, the library's address and the code the plugin showed, and the kept snapshot is delivered into the new project (`deliver.cjs`). Any page can post to the router, so a kept snapshot is taken only by its code, which only the plugin that sent it was shown, and refused where it says it came from another file than the address given; the editor names nothing of what is kept. Without a code it asks a name, the library's address and the id the snapshot plugin prints when it refuses a file no project claims. It writes the project's home and context document, at `<root>/<name>/figma-design-system/`, the root being `TOOLKIT_PROJECTS_ROOT` or else the folder that holds the toolkit's checkout (`projects.create` in `tools/snapshot/projects.cjs`, the registry's one maker) and serves it from then on, so its settings are kept there as any project's are, and every tool reads it by `--project`. Snapshot the library next to bring its components in.

**The docs site and the editor link to each other.** A team reads a component in the project's docs site and changes or proposes its API here. Opened with `--project`, the editor listens on the project block's `editorPort` in its context document (9250 where it states none; `--port` overrides it), and the docs site's component page offers **Propose a change**, opening `/?component=<name>` there; only where the site itself is served from this machine, never on a published copy. Back the other way, a library component being read shows **Docs**, its page in the site the figma-audit service serves at the project block's `port`, found in the site's last build (`api/index.json`); none until the site is built. The project block owns both ports, so neither tool takes a setting of its own.

`--snapshot` needs no registered project: anyone who has run the snapshot plugin can open what it wrote. The folder is read through the store's layout (`tools/snapshot/store.cjs`), and a repo's `snapshot.config.json` `paths` move it, as for the docs site. A repo the registry knows keeps its own settings (state axis, option order), as `--project` reads them; with no project the house settings apply, and Push to Figma and Pull from code stay off, since both need a project's files. It still runs from a toolkit checkout.

One editor for every project, served as the docs site is: one tool in the toolkit, a project keeps no copy (`tools/toolkit-check/owned.json` fails one), and each server serves one project's library and never switches; a second project is a second server (`--port`). Each capability needs what it reads, and a menu item that is off says which is missing:

| Capability | Needs |
|---|---|
| Edit a contract, keep drafts, propose | nothing: the house settings |
| Keep settings for everyone on the library | a project: one registered, or made from Settings |
| Open the library's components, its tokens and icons | a snapshot (`--snapshot`, or a registered project) |
| Pull from Figma | the component in that snapshot |
| Push a new component to Figma | a registered project, and a scratch file |
| Update a library component in place | a registered project, its library file open in Figma with the Desktop Bridge |
| Push a new component's stylesheet to code | a code repo and its styles folder, set in Settings |
| Pull from code | a parity mapping for the component: a governed repo's (`parity` in its `snapshot.config.json`), or a library built elsewhere that its context document compares (`code.parity`) |

Restart the server after changing `serve.mjs`, `props.mjs` or `anatomy.mjs`: the server imports them. The page's own files are read on each request.

**The bar.** Each sidebar's toggle sits on that sidebar's side and stays there: **Components** and **New component** on the left, the theme (**System**, **Light**, **Dark**, the docs site's switch, `docs-site/src/scripts/theme.js`) on the right, on every tab; the preview draws in the theme chosen. Under it, the component's own bar spans the palette and the work: its name, **Figma**, **Code** and **Preview**, and the tabs, which stay put whichever tab is open; each tab sets the columns under it, and Variants takes the palette's and the preview's room for its grid. **Preview** shows or hides the preview and JSON, docked beside the work as a preview compared with the work is; Variants takes its room and the palette's for the grid, the toggle kept in its place, off. The address keeps the component, tab and pane, so a reload or a shared link opens the same view.

**Figma** and **Code**, at the end of the component's name row, sync it with the project, each side through the toolkit tool that owns it:
- **Pull from Figma** reads the snapshot again and reopens the component; a new component has nothing to pull.
- **Push to Figma** draws a new component through `to-figma.mjs` into the library's scratch file, on a page of its own; never the library.
- **Settings** (the bar's end) holds the library's scratch file and its source of truth (Figma, or the contract: `official.mjs --switch`). Both are kept in the project's context document (`draw.scratch` and `source` in the library's audit settings), for everyone on the library. Where no context document holds them, the scratch file is kept in this browser and the source is Figma's. Push to Figma with no scratch file set opens Settings first. Settings also connects a local git repo as the project's code repo: `init.mjs --project <label>` runs dry and its plan is shown, then it runs when confirmed, and the library's snapshots go to the repo from then on. Once a repo is connected, its styles folder, class prefix and framework are set there too (`paths.componentStyles`, `styles.naming` and `framework` in the repo's `snapshot.config.json`, through `projects.setRepoConfig`); the framework sets the naming its markup carries, React class naming and web components element naming, with a prefix that ends in a hyphen, as a custom element's name needs.
- **Only in code**: a library built elsewhere lists, under the library's components, those its code has and Figma does not (the docs site's Coverage rule, `code-inventory.mjs`). One opens to be read as a library component does, from its last reading (`from-code.mjs --code-only`; Pull from code reads it again), said *Only in code*; Edit as draft makes a draft of it, said *Drafted from … in code*, which pushes to Figma as a new component and never offers to update a library component it does not have.
- **Pull from code** runs `from-code.mjs` and opens the code's contract as a draft to compare, or says what that tool said. It reads any project the parity engine reads, on any host it renders (a Storybook, a site's fragments): the code's props from what the host declares, or from the mapping's `controls` where it declares none, said as such.
- **Push to code** writes a new component's stylesheet into the repo's styles folder (`to-code.mjs --contract`), where one is set: a draft's sheet, said so at its top, which never replaces another file and which to-code generates over once the component is in the snapshot; where the repo names a framework (React, web components or Kirby), also its component (a Kirby snippet), parity mapping and story beside its spec (`to-markup.mjs --contract`); and hands the component to the frontend-build skill as a brief.
- **The contract as the source.** Where the library takes the contract as its source (`source: "contract"`, `component-contract/official.mjs`), the components open as their official contracts, not Figma's reading. A linked draft's **Save as official** writes the draft over its component's official contract (refused where that contract changed since the draft was made). A component Figma differs on says *Figma is behind*, with **Copy brief for Figma** (each value to change, and what Figma has) and **Take Figma's version** (every difference taken; to take some, Edit as draft, change, Save as official); one Figma no longer has offers **Drop the official contract**, one new in Figma **Take as official**. **Update the library component…** is then held to Figma's reading, not the official contract, so it can bring Figma up to it.
- For a component the library already has, either push becomes **Propose**: a proposal file of what changed, for review. Neither side updates the other.
- **A linked draft.** **Edit as draft** on a library component makes a draft that remembers the component it came from, as it was then; the bar says *Linked to Button in the library*. Its **Figma** menu offers **Push as new component** (into a scratch file, as above: the usual way, to review first) and **Update the library component…**, offered, not recommended: asked first, it updates the component set in the library file itself through `to-figma.mjs --patch` (a version saved in the file's history first; each variant that stays keeps its node and key, so instances in every file stay linked and take the change when the library publishes; a variant the draft no longer draws is removed), then reads it back (`--verify`). Refused, with nothing drawn, where the library's component is no longer what the draft was made from (the snapshot read again and compared, then the library file itself, read live by the snapshot's own walk): open it again and redo the change, or push it as new. Not offered for a draft with no parts.
- A run shows at the foot of the page, with its seconds, once it has taken a second, and stays half a second at least. One runs at a time: while it does, the menus say to wait.

**Components.** The drafts kept in this browser first, then the connected library's components. A new component is a draft from its first edit, kept as its name changes, so leaving it asks nothing; two of one name are two drafts. Where this browser will not keep it (storage full or off), the page says so and leaving asks. Opening one over changed work from the library asks to **Save as draft** or **Discard**. Unchanged work goes without asking. In two tabs, a draft open in both shows each tab's edits in the other, a reload goes on with that tab's own page, and a tab closed on library work another tab has since written over keeps it as a draft. A draft begun from a library component remembers it as it was; opened after a snapshot changed it, the page says what Figma changed since and offers Figma's version, the draft kept.

**Props.** The **Kinds** tab holds the blocks by the side they exist on:
- Figma and code: Options, On / off, Text, Swap and Slot.
- Code only: Number and Event.
- Figma only: Interaction states.

The **Library** tab, A to Z, offers the props two or more of the library's components share, already named. Click a block, or drag it into the list; its dialog sets it up: the kind first, every kind a tile of one size, then the name and that kind's fields, then where it exists (Figma and code, Figma only, Code only; fixed, and said why, for a kind one side lacks). No section is boxed: a label over its fields, space between. A new Text, Swap or Slot prop brings its part into the outer box, linked to it. Renamed, it takes along the part still named for it. A search, in a picker or the palette, finds a name holding every word typed, in any order: `bac wa` finds `Background/warning`. Rows reorder by their handle (drag, or the arrow keys) or their menu. A part is duplicated from its menu or with Ctrl/⌘+D, and copied and pasted with Ctrl/⌘+C and V (into a container chosen, else after the part), within the component and at the defaults, what is inside it coming too. Dragged, in this list and in the parts tree alike, a copy of the row follows the pointer, the row shows dashed where it will land (inside a container, at that depth), and the rows around ease aside, over 200ms, not at all with reduced motion. A name being typed completes inline to the library's own names. An Options prop offers the options the library's props of that name have. An option is renamed in place: double-click its chip, or Enter on it; Enter keeps the name, Escape the old one, and on Save the default, the variants and the combinations not drawn follow it. **Often added** under the list offers, in one click, the props most of the library's components that have one of these also have.

**Anatomy.** The component's parts in a tree, the part blocks in the panel beside it (hidden on Variants). Choosing a part in the tree opens it in a modal: the props to draw the component at on the left, the component drawn in the middle, as large as it fits or at its own size (**Fit** / **100%**), the part's rows on the right; in its footer Delete part (the modal then shows the part it sat in), arrows that move it among the parts beside it, Add inside and Close. A colour's swatch, in a row or a picker, is light or dark as the page is, as the drawing is. A part's **Position**, as Figma's panel has it: in the flow or absolute, and out of the flow its offsets drawn as its box, a number on each side pinned to that edge and *auto* on a side left free; a number on both sides stretches it with its box, with no width or height of its own (a focus ring, −4 all round). On the stage, a click inside a part that paints only its outline chooses what is under it, as Figma chooses a shape with no fill by its stroke. An image fill draws the snapshot's preview of its component (`previews/`), light or dark as the page is; where there is none, a placeholder says an image is there. A part is chosen there on the stage or in the trail at the top too, the stage choosing as Figma's does: a click chooses the outermost part under the pointer at the levels open (the part chosen and every part it sits in), so a second click goes one level in, and ⌘ or Ctrl chooses the innermost at once; the part a click would choose is outlined thinly while pointed at, and the component's name above its outer box chooses that box. The part chosen is outlined, and its rows are listed: a name and a control each, a value not set yet dashed and saying **Add**; every kind has an **Opacity** (a state's dim, by its token), shown on a component being read only where it is set. A chosen container shows its padding and gap on the stage as dev tools do, tinted, a number on each; they are set in its rows, the one place each is set, and a part is moved in the tree or by the footer's arrows (a drag across the stage chooses nothing). A part block adds its part at once, named for its kind, into the part chosen (after it, if that is no container), or where it is dropped in the tree; its name is ready to type over. A part just added is added or cancelled, as a new prop is: its footer says **Cancel** and **Add part** in place of Delete part and Close. One added with Add inside goes back, either way, to the part it was added from; the outermost closes the modal. × and the backdrop take back every part still being added, Escape the one shown; choosing another part keeps it. Backspace or Delete, while no field takes the keys, deletes the part shown (or cancels it, while it is being added), and the modal shows the part it sat in, as Delete part does.

The stage draws the component at any of its props' values, listed as Figma's instance panel lists them: an option a menu, an on/off a switch, a reset beside the heading. An on/off that only shows a part is listed too: the part is drawn as any part, its switch On, and turned Off it is not drawn; it is a view, so an edit stays the variant's. At the defaults an edit is the component's own. At other values it is that variant's: written to the variant layer holding exactly those values (made where there is none, after the layers of fewer props), and taken out where it repeats what the layers under it draw (`variants.mjs`). A dot marks each row the variant changes: filled where its own layer does, a click putting it back; hollow where a layer of fewer props does, a mark that says which. An edit is never written to a layer of fewer props, which holds at other values too; where one drawn after the combination's own sets the same field, the edit goes in a layer of its own after it, and no layer moves. A part's name, kind, container and links are the component's, offered at the defaults only, and so is adding a part. Deleting and moving are not: **Delete from this variant** (its values on hover; Backspace too) takes the part out of the variant shown alone, at the defaults the default combination alone (a layer naming every variant prop at its default, drawn last as whole combinations are; an on/off that is no variant, an instance or a code-only prop left out, so the part stays gone whatever they are set to), as a Figma variant is its own frame, while **Delete from all variants** in its row menu takes it out of the component. At other values it takes the part (and what sits in it) out of that variant alone, its layer's `remove`, and the arrows move it among the parts beside it there, their positions set in that layer; Undo is offered, and a part deleted there opens saying it is not drawn, with **Put back**, and its row in the tree carries a chip of the values it is not drawn at, (*Not in lg*, the whole condition on hover): not in it at all, not hidden. Moving a part into another container stays the component's. **Ctrl+Z** (⌘Z) undoes the last change of any kind, and Shift+Ctrl+Z redoes it, a step each (what is typed into one field one step), the history begun again for each component opened; a text field keeps its own undo while it is typed in.

The parts:
- containers, and slots, which hold their default contents as Figma's do: direction, where the parts sit across it (Align) and along it (Justify), as CSS names them, gap, padding (in the rows: left and right, top and bottom, or each side once the toggle beside them is on), background, corners (one radius, or each corner by the same toggle), shadow and border;
- text: its words from a Text prop or fixed, a text style, a colour and its alignment in its box (Left, Centre, Right);
- an instance of a library component, which a Swap prop can swap;
- a slot, filled by a Slot prop;
- a shape: a rectangle or an ellipse, its fill, border, a rectangle's corners, and its size; a library's drawn vector, its fill and size.

Each part is sized as Figma sizes it: its content's (Fit), its container's (Fill) or fixed pixels, with a minimum for a side that fits or fills.

Any part can be shown by an On / off property (a False/True variant restyles and shows nothing). Parts that only some variants draw are rows under their parent like the others, a chip of the values that draw them (*Only in Loading*, the whole condition on hover) where a part some variants take out has one saying where it is not (*Not in lg*). An ellipse's arc (a spinner's ring) is drawn as Figma draws it. Values are tokens from the project's snapshot. A field offers the variables Figma scopes to it; for a snapshot taken before scopes were recorded, it offers the families the library already uses there. Parts that only some variants draw are chosen too: the stage then draws the component at the values that draw them. Parts move by drag (before, after or into a container), by their handle's arrow keys, or by the Inside row. Part blocks drag into the tree too. The tree opens one level deep, each container in the outer box folded; a container opens on its own, or **Expand all** and **Collapse all** turn the whole tree. A part's look that Figma has drawn reads as an inspect list: its values as text, without the controls' chrome, and what is unset left out.

**Variants** lays every combination out as a reference sheet does (Propstar), schematic: the last props across while their columns fit a dozen, the rest down, each nesting the next, a dot a cell where Figma draws it and a cross where it does not. The grid takes two thirds and the list of changes the rest (stacked on a narrow screen), the grid as wide as its cells, its columns one width and never under 3rem, an on/off across its last row said as its prop's name over Off and On, so cells look alike from grid to grid; a grid larger than its box scrolls inside it, its column headers kept in sight, and the cell under the pointer is tinted with the two headers that name it. The cell chosen, the defaults to begin with, is ringed, and beside the grid is one list of what that combination draws differently from the defaults, whichever layers say it: Part | Default | Here, a fact a row as Carbon's style tabs and Figma's Compare changes give it, the default faded, colours with their swatch and a number token with its value (*Loading/opacity 0*), a setting changed alone named in the row (*Outer box border colour*) and one changed with others listed in the cell, a part added or removed said as Absent and Present, with the parts inside it counted. Read-only, as they are Figma's. A prop seen only behind an on/off (an icon's swap behind Show icon) is listed under it in Props, and its modal sets the on/off, or says so where a Figma variant adds its part. **Include booleans**, at the grid's top right where the component has any, crosses the on/off properties that only show and hide parts too, as Propstar's table does; a cell with one off lists the parts it hides as Absent.

On Variants, the grid is the page. A header is a button: its value alone, at the defaults, is what the panel beside the grid says the changes of. A diamond marks a cell whose values change each other, drawing something none of them draws on its own (Secondary and Danger together, a fill neither gives alone); the grid's heading counts them, and the panel splits a cell's changes into what its values each make and what they make only together. The layers themselves are edited in the JSON, and in Anatomy at the values chosen. On the stage, a part is dragged to another place as in Figma: the part itself follows the pointer, takes the place of a part whose middle it crosses along its container's flow while the others slide aside to make room, and goes inside a container over its middle; let go, it settles there, and Escape slides it back. At a variant it moves among the parts beside it, there alone (`stageDrag` in `editor.js`).

**Preview** is a sketch from the contract. It draws the structure and tokens, alignment and sizes included. Placed components are drawn from their own contracts with the instance's values, and icons from the project's SVGs (an icon is a name whose last segment the project exports and that is no component of the library's own; drawn at its set's size axis, the settings' `sizeAxis`, else the sizes it was exported at), an icon given no colour in its own (the variable its glyph is painted with, which the snapshot records from plugin 0.63.0; its Colour field shows it until another is chosen). It is captioned as a sketch, because a contract holds structure and intent, not every pixel. Pointing at a part in the tree outlines it there.

**JSON** is the contract, editable: **Apply** reads it back after checking it, saying where each problem is, and **Undo edits** drops the edits. **Download** and **Copy JSON** take it away.

**Reads**, for the connected project:
- its settings: its `audit-settings` merged over [the house's](../../standards/audit-settings.json);
- every stored `contract.json` in its components folder, made whole from the `figma.json` beside it;
- its token snapshot, read again when the snapshot is taken again (no restart): colours (with dark values, from the mode called Dark, as `tokens.cjs` picks it), lengths, text styles, effect styles and variable scopes (`anatomy.mjs` `tokenLists`; not built on `tools/snapshot/tokens.cjs`, which looks one name up across collections, while this lists every token per collection and runs in the page too, where a CommonJS module cannot load);
- its icons, for the preview.

**Writes** nothing itself: the contract leaves through the browser's download. `/sync` runs the toolkit tool that owns each side, which writes what it writes (`to-figma.mjs` a drawing in the scratch file; Settings the library's `draw.scratch` and `source` in its context document, and a connected repo's `init.mjs` files and its styles settings; `to-code.mjs` a new component's stylesheet; `from-code.mjs` its report under the project's `parity/from-code/`).

**Needs:** Node 22.12+. The page uses the toolkit's UI stylesheet ([system.css](../docs-site/src/styles/system.css)), served from where it lives, and Lucide's icons (`icons.mjs`, ISC, notice kept).

## What it adds to the contract

Three prop fields a contract made here sets by hand; a derived one carries `axis` and `figmaValues` already:
- `axis`: a boolean drawn as a False/True variant, rather than a boolean property;
- `only`: `figma` or `code`, for a prop one side has and the other does not. Number and Event are always `code`; interaction states are always `figma`;
- `figmaValues`: an enum's options as Figma spells them, which the kebab-case `values` lose or the house's sentence case would change (`lg`, not `Lg`).

`anatomy` is written in the derived contract's shape: an id per part from its path, `parent`, `order`, `layout`, tokens by name, and `content` as `{prop}`. Each prop gains the `shows`, `sets` or `swaps` its parts name, so a link follows a prop through a rename. A part read from a contract keeps what the editor does not set (alignment, fill, maximum sizes, per-side borders, overflow) and writes it back unchanged. An instance's own layers ride inside it, and are not parts of this component. A part takes its name from its id, and carries its own `name` where the id cannot say it back (a repeat, a layer a boolean shows, "UI note" as `uINote`); its id stays. A new contract starts with `variants` and `invalid` empty; one opened keeps Figma's, shown in the Variants tab, carried through renames and pruned with a deleted prop.

## Test

```sh
node tools/contract-editor/test-props.mjs
node tools/contract-editor/test-anatomy.mjs
node tools/contract-editor/test-variants.mjs
node tools/contract-editor/test-serve.mjs                         # --snapshot, bare and through a repo's config
node tools/contract-editor/test-editor.mjs [--fixtures | --project <label> [--fixtures]]   # headless Chrome; SHOTS=<dir> saves screenshots
```

`--fixtures` alone runs every check against `sample/`, a made-up library of eleven components, their tokens and icons, kept as JSON by hand in the store's layout. It holds what the named checks need: a placed component with props of its own, icons from SVGs, parts only some variants draw, a stretched part, a focus ring, combinations not drawn, an option of one value. `bin/check` runs it. Add to the sample when a check needs a shape it lacks; it never holds a project's library.

`test-editor.mjs` drives the page as a person would. Clicks, drags and keys add, move and edit props and parts; dialogs check before they save, and parts are chosen and edited on the stage, at the defaults and at a variant. JSON is applied and refused. Drafts are kept and opened, a reload restores the page, and a second tab follows the first. With `--project` it also covers what only a library gives, on any library: suggestions, components, the pickers. `--fixtures` adds the checks that open components by name (Button, Badge, Nav panel, Search input, Avatar, Contact card, Option row): alone, on the sample; with `--project`, on that library, which fails without them. `--project snapshot --snapshot <dir>` runs it on a snapshot folder. `bin/check` runs it on the sample with `--fixtures`, and with each registered project.
