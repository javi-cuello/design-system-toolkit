# Pixels are for eyes, never for gates

What the run's pictures are, the two advisory forms pixels take in the loop, and one candidate rule not yet proven. [SKILL.md](../SKILL.md) links here.

## The pictures

The code is `tools/parity/shots.mjs`, called by the run's `--shots`. All of it is printed, and none of it fails a run.

| What | How |
|---|---|
| Folder | `parity.shots`, or `--shots=<dir>` |
| A picture per target | In each tier, as the run left the page, once its images in the clip have painted |
| Against the last set | Compared pixel by pixel with the set the last accepted run kept |
| Keeping a set | `--accept --shots` keeps it |
| Each screen | Beside a frame picture, in the tier the frames are drawn in: the first of `parity.tiers` |
| Frame comparison | As 24px regions by mean colour |
| Contact sheet | Design, page and heat, in `<dir>/frames` |

A scoped run with `--shots` is also how one screen's states are looked at. One word names a target or, failing that, its family. `bin/parity contact --shots` is every `contact--…` state. No project keeps a screenshotter of its own (`owned.json`).

## The two advisory forms

Every gate is arithmetic on data. Pixels stay in the loop in exactly two advisory forms. The one class no data can see is compositing and rasterisation itself. Two paints blend into one pixel, or a border drawn twice reads as one blurred edge.

- **A screenshot per render, diffed against the last kept set**. Paint order and overlap are what no property comparison sees, such as a ring painted under an image. Fonts move pixels on their own, so it informs and never blocks. Its data sibling, gate 12, is the one that gates.
- **The contact sheet**. The design frame travels with the snapshot as a picture. A region comparison points eyes at where the composition disagrees. It uses mean colour per cell, never per pixel, because two rasterisers never agree.

The receiver builds the sheets, design beside page beside a heat overlay. It opens the folder as a side effect of the snapshot itself.

Why not a gate:

- The field's evidence says frontier vision models detect under half of real single-property changes.
- The reference project's four worst escapes each measured identical to their frames. A person found them holding the two side by side. Making that look automatic and unskippable is the honest response, not making it a gate.
- Region averaging is blind to hairline-scale defects. That is acceptable in an eye-pointer and disqualifying in a gate.

## A candidate, not yet a rule

**The product stays on the system**. A gate over page templates would refuse four things:

- an inline style;
- any class but the utilities;
- a bare control the system has a component for;
- a raw colour or length.

Parity proves the components and the screens, and cannot see a page that walks past them. Shopify had 14% of its admin off Polaris a year after adoption, with a dashboard watching.

This comes from research rather than a run. Carry it as a check, not as a gate you trust.
