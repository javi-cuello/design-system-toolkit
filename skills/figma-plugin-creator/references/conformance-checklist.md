# Conformance checklist (run top to bottom)

## 1 · Manifest
Required: name · editorType (array) · documentAccess:"dynamic-page" · main · ui (if any) · networkAccess. `api` pinned. `id` always (development plugins lose relaunch data and `pluginData` without one) — flag any id change as data-loss risk. relaunchButtons only if code calls setRelaunchData.
**Permissions, the silent one:** `grep -nE 'figma\.teamLibrary|figma\.payments|figma\.currentUser|figma\.activeUsers' code.js` — a hit needs the matching entry in `permissions` (`teamlibrary`, `payments`, `currentuser`, `activeusers`). Missing it does not stop the plugin loading: every call to that API throws `"<name>" permission not specified in manifest.json` at runtime, and a plugin that catches or races those calls turns the throw into an empty result, which reads as "this file has nothing". One plugin shipped three versions and passed two live test runs that way. `standards/tests/check.sh` enforces the `teamlibrary` case.

## 2 · Banned sync APIs (must be clean BEFORE adding documentAccess)
grep -nE 'getNodeById\(|getStyleById\(|getFileThumbnailNode\(|getLocalTextStyles\(|getLocalPaintStyles\(|getLocalEffectStyles\(|getLocalGridStyles\(|getVariableById\(|getVariableCollectionById\(|getLocalVariables\(|getLocalVariableCollections\(|\.mainComponent\b|\.instances\b|\.consumers\b|currentPage\s*=|figma\.root\.findAll|\.masterComponent\b' code.js Any hit → convert to the …Async equivalent (or PageNode.loadAsync / loadAllPagesAsync) BEFORE the manifest gains dynamic-page. Behaviour-changing: adding dynamic-page (sync APIs throw) · adding networkAccess (fetches blocked) · adding/changing id (storage re-keyed). Inert: editorType, api, relaunchButtons.

## 3 · Network truth
grep -cE 'fetch\(|XMLHttpRequest|WebSocket' code.js ui.html 0 hits → allowedDomains ["none"]. Hits → enumerate the real domains; scheme + subdomain wildcard rules per the standard. If any fetch target is a CDN serving an npm package (icons, fonts, any versioned asset) and it's unpkg.com with no fallback: needs-decision — unpkg rejects fetches from a plugin UI's null origin outright (confirmed, not theoretical); jsdelivr (cdn.jsdelivr.net/npm/...) is the confirmed-working default. See references/network-fetch-patterns.md. Also confirm any such fetch targets a PINNED version, not @latest.

## 4 · Metadata
package.json version (SemVer, source of truth) · code.js header comment mirrors it, and carries `· standard vX.Y.Z` naming the `skill-standard.md` version this plugin was last audited against (skill-standard §B 8 — a lag is the signal, an absence is the defect; update it only when an audit actually happens) · CHANGELOG.md · README.md with "Data this plugin stores" · tsconfig.json present (copy from assets/tsconfig.json.tpl if missing) · `// @ts-check` as code.js's second line (right after the version header).

## 4b · Settings hygiene
For every `settings.<field>` read in code.js: confirm the property it flows into matches what the field is named/described for. A value landing on a decorative/chrome property unrelated to the setting's stated purpose (e.g. an "icon stroke width" setting silently driving a boundary-chrome stroke) is a needs-decision finding — re-derive the setting's real intended purpose before changing anything; changing an unrelated setting's default is not a fix for a wiring bug.

## 5 · ui-base drift
Extract the block between `/* ui-base vN start */` and `/* ui-base vN end */` in ui.html (any version: the marker is bumped with the block); diff against assets/ui-base.css. Drift → re-inline the canonical block only. Absent → **inline it: mandatory, not offered** `[maintainer ruling, skill 1.1.0]`. Reconcile by stripping plugin CSS that duplicates base control styling while keeping plugin-specific rules, and close with a visual retest in light and dark theme. Never restyle existing bespoke UI beyond the block, and never touch code.js logic. *This line read "offer to inline (cosmetic change; needs approval)" until 2026-08-09 — the wording the 1.1.0 ruling retired. SKILL.md and case P4 both carried the ruling; this reference did not, so an agent running the checklist top to bottom as SKILL.md directs would have read the reference and merely offered.*

## 5b · Runtime traps that produce no error
Each of these shipped in a real plugin in this repo and was found in a Figma file, not in review. They have one shape in common: the plugin looks like it is working.
- **A cache set before its work finishes.** Memoise the **promise**, not the result. `if (!cache) { cache = []; …await… }` means a second caller arriving mid-flight sees a warm cache, skips the fast path and queues behind the slow one — a window that sat blank for six seconds while the fast answer was already in hand. Write `if (!p) { p = doTheWork(); } var out = await p;`.
- **A guard that cannot tell a timeout from a refusal.** Racing a slow API against a timeout is right (`getVariablesInLibraryCollectionAsync` genuinely never returned for one collection: 6.9s, twice, against 1ms for its neighbour). Catching the rejection and returning a neutral value in the same wrapper is not: it turned a missing manifest permission into "this file has no library collections" for three versions. Report the first real error you swallow.
- **`setExplicitVariableModeForCollection` / `clear…` take the collection NODE.** The id-string form throws `Cannot call … with a collection id in incremental mode`, and a pin whose collection cannot be resolved at all cannot be removed by any route — count those and say so rather than catching and moving on.
- **An extension's pin is cleared through its PARENT.** `clearExplicitVariableModeForCollection(extension)` does nothing: no throw, no change, and a `catch` around it sees nothing to catch. Setting the extension's mode replaces the parent's entry rather than adding one — they share a slot — and only the parent clears it. Count leftovers from what is still on the node afterwards; a call that does nothing cannot be detected any other way.
- **`loadAllPagesAsync()` is not a one-off cost.** Every page stays in memory for as long as the plugin runs, and in a large file that shows up as Figma itself feeling heavy — the plugin window stutters when you drag it. Prefer `page.loadAsync()` in a loop that can stop early, and only when what you already have does not answer the question.
- **A remote collection's id is not stable across published generations.** `VariableCollectionId:<key>/<local>` — the local half changes when the library republishes, so comparing whole ids reports "not pinned" on a layer that plainly is. Compare the key.
- **Depth is a decision, not a detail.** A mode pinned on a nested frame overrides the one you set on its parent, so a shallow "clear" reports success and changes nothing on screen.
- **`getNodeByIdAsync` can hang on an id inside an instance.** It never resolved for sublayer ids read from `instance.overrides`, and the bridge reported a lost connection rather than an error. Build an id map from `instance.findAll(() => true)` and look the ids up there.
- **An instance read before it is appended into a SLOT keeps stale sublayer ids.** Reading its children (to load their fonts, say) and then `appendChild`ing it into a slot leaves those nodes detached: later writes fail on ids that no longer exist. Load fonts from the main component instead, or read after appending.
- **Overrides on a slot's contents are listed on the instance that holds the slot,** not on the nested instance. A copy that gathers overrides per instance misses them; gather them across the whole frame.
- **A GRID frame's tracks are fragile.** A HUG track passed with a `value` is stored as FIXED, so pass `{ type: 'HUG' }` alone; setting `primaryAxisSizingMode` on a GRID frame resets its tracks; `setGridChildPosition` takes only a child with an anchor index of 0 or more.
- **A gradient's stops carry their own variable bindings,** apart from the paint's. Copy them with `createVariableAlias`, or the stops render in their raw colour (white, here).
- **SLOT properties cannot go through `setProperties`,** and a renamed property keeps its `#id` suffix: map properties by suffix, and fill a slot by appending to it.
- **A text written by segments loses its text style.** Setting font, size or fills per range on a text that had a style leaves it styled "literal": nothing throws, and it looks the same until the style changes. Set the style (`setTextStyleIdAsync`) after the characters, or only the properties that differ.
- **A copied frame is checked field by field against its source, not by eye.** A rebuild of 114 screens looked right and had lost text styles on 459 loose texts, a variant override on 8 Avatars nested in slots, and 16 direct icon swaps. Walk both trees by position and compare every field (style ids, variant values, each instance's main component) before calling the copy done.
- **In the UI, an `<svg>` has no `hidden` property, and `var status` is `window.status`.** `svg.hidden = false` sets nothing, so the icon never shows; use `toggleAttribute('hidden', …)`. A top-level `var status = el` turns the element into a string; name it anything else.

## 6 · Retest protocol (after ANY manifest change)
Re-import manifest → run in a trivial file → run in a large multi-page file (no sync-API throws, no unexpected "loading pages") → verify stored settings still load → version bump + changelog.
