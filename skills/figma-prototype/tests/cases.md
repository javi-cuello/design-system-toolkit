## P1 · A Figma prototype knows the system, starts from a reference and says what it read — *traced*
*Was frontend-build T14, moved with the section on 2026-11-11.*
Fixture: "prototype an edit-employee flow in Figma" in a file whose screen template has three reference screens, one a table.
Assert: before composing, the session lists the library's components (system MCP `overview`, or the library listing), runs `figma-components-audit` (or `get_screen_recipe`) for the reference screens and starts from a copy of the table screen, walks `knowledge/README.md` and the pages the flow touches (tables, dialogs, forms, feedback) where the toolkit is present; each frame carries the shared `fca` / `receipt` naming the reference, components, invented items and pages read; `FCA.composedFrame` with `{ receipt: true }` is clean. Where the knowledge base disagrees with the reference (a Sort button where it sorts in the headers), the frame keeps the reference's drawing and a plain-text comment on that layer, posted by `figma-feedback.mjs --on` as the agent's account, a title and two or three bullets (the conflict, the option, the question) and a `More:` link to the knowledge section, asks the designer; a disabled input standing for a read-only value is fixed before the check. Fonts are loaded once per call, and variants are set by the option names Figma shows (`Added`), not the snapshot's lowercased ones.
Negative: a flow built from the bare template, from only the components a reference holds, or with no receipt; a knowledge-base conflict that stops the build, or is silently redrawn against the designer's pattern; a comment of quoted guidance and file paths; a font loaded per text node until the call times out; a variant set to `added`.
Traced: 2026-11-10 for 2.11.0 — to frontend-build SKILL.md *A Figma prototype* (now this skill's *Compose*); 2.12.0, step 5; 2.13.0, step 4; 2.15.0, step 5's poster.

## P2 · Feedback on a prototype is read first, routed once, and never re-asked — *traced*
*Was frontend-build T15, moved with the section on 2026-11-11.*
Fixture: a file with a composed People flow carrying receipts; a person's comment on its dialog title ("this one dialog reads better as New employee"), a person's reply under an earlier question from the agent's account on the toolbar's Sort button ("keep it, the headers are too small"), and a thread whose last message is the agent's reply.
Assert: before composing, the run lists the open threads (`scripts/figma-feedback.mjs`): the two, not the handled one; fixes the title on the frame; a comment pinned to a whole frame ("remove button") is traced by its `offset` to the header's "+" button under the pin, which goes from every screen of the flow that shows it; replies are posted by `figma-feedback.mjs --reply`; records the Sort answer as a dated §6 decision, Scope `Product`, with the comment's link and the designer as who decided; replies to each, as the agent's account, with `Routed:` where it went (the commenter being the maintainer, who may rule); on the next composition, applies the Sort ruling with no new comment and names it in the receipt's `rulings`.
Negative: a new composition before the open threads are handled; the Sort question posted again; a ruling written as a memory note or a knowledge-base rule from one project's comment; a ruling taken from someone the context document does not name as able to rule; a thread resolved or left with no reply; a list served when the agent's own identity is unknown; a fix made on the commented screen while the flow's other screens keep the thing it removed; a fix that removes what the reference brought kept on the frames only, with no §6 Screen decision, so the next copy brings it back.
Traced: 2026-11-11 for 2.18.0 — to frontend-build SKILL.md *A Figma prototype* (now this skill's *Compose*), step 0 and *Feedback on a prototype*, step 2 (§6, Scope `Product`); first traced for 2.14.0, its Negative widened for 2.19.1; the header button case met real input that day (one comment, three screens fixed).

## P3 · The product file is filled from evidence; feedback is logged with notes, read every ten, and checked by the eval — *traced*
*Was frontend-build T16, moved with the section on 2026-11-11.*
Fixture: a project with no product file, a Figma file whose pages name its sections, and a code repo with a playground of product pages and sample data; nine lines in `tests/evals/feedback.jsonl`; a person's comment that becomes the tenth; a product decision dated 2026-11-11 that a later comment contradicts.
Assert: before composing, the run drafts `product-context.md` from that evidence, each line with its source, asks at most five questions with choices on the gaps, and writes it only after the user's yes; the close posts the reply and logs the thread with its area, level and a note in one call; the tenth line prompts a reading, and the run reports kinds named from the notes, not the five areas, with the one change that would have prevented the largest; a new product decision goes into §6 with Scope `Product` (not the product file) and its date into the eval task's `rulings`, and a run whose receipts do not name it scores below green with "rulings not applied: <date>"; the contradicted decision is offered to the user to retire, struck through in place with `retired <date>: <reason>` in its Why, and its date leaves the task's `rulings` once retired.
Negative: a product file invented with no source per line, or written before the user's yes; more than five questions, or questions about lines the screen does not need at run time; a thread replied to and not logged, or logged with no note; the reading reported as area counts; a decision recorded without joining the eval task, or in the product file; a project without a product file or eval task stopped rather than run with that piece skipped and said; a decision offered to retire only for going unused; a decision deleted rather than struck through, or retired by a new row.
Traced: 2026-11-11 for 2.18.0 — to frontend-build SKILL.md *A Figma prototype* (now this skill's *Compose*), step 0, and *Feedback on a prototype*, steps 2–4.
Runs: node --test tests/test-feedback.mjs — "kinds counts the log by area and by level, largest first, and lists every note by area"; node tools/skill-evals/test-eval.mjs — "figma: a ruling the task lists is applied when some frame's receipt names its date; a missed one says which"

## P4 · A project's guidance page is read beside the knowledge page and wins; two decisions on one topic become one — *executed in part*

Assert: the first project's run reads the knowledge page and its guidance page, sorts from the toolbar menu with no Figma comment on the conflict with the reference and names both pages in the receipt; the second follows the knowledge page and says no guidance page exists; at the feedback reading, the run offers a `guidance/shell.md` gathering the two header decisions, each line with its §6 date, and writes it only after the user's yes.
Negative: the knowledge page's advice applied over the project's page; the guidance page copying the knowledge page; a page written without the yes, or with a line that has no source; a run that stops because `guidance/` is absent; a guidance line with no §6 date, or one left standing after its decision is struck; a page applied over a live §6 decision it contradicts.
