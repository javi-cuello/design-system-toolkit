# Code candidates and sources

The practices for front-end code that no run here has proven yet, and the primary sources behind code-standard's rules. They moved here from code-standard on 2026-10-11, so that both front-end standards keep only proven rules and the depth lives in the knowledge pages (toolkit-standard §D 21). A candidate is not a rule and nothing may cite it as one; an audit raises one as a recommendation with its source. When a run proves one, it becomes a code-standard rule and leaves this file.

**Supporting code-standard's rules** (each names the rule it backs):

- code-standard rule 1 — WHATWG: "Authors are strongly encouraged to view the `div` element as an element of last resort, for when no other element is suitable." <https://html.spec.whatwg.org/multipage/grouping-content.html#the-div-element>
- code-standard rules 8, 9 — W3C *Using ARIA*, first rule: "If you can use a native HTML element or attribute with the semantics and behavior you require already built in… then do so." <https://www.w3.org/TR/using-aria/>. APG: "No ARIA is better than bad ARIA." <https://www.w3.org/WAI/ARIA/apg/practices/read-me-first/>
- code-standard rule 2 — WCAG 2.2 1.3.2 Meaningful Sequence and 2.4.3 Focus Order. <https://www.w3.org/TR/WCAG22/>
- code-standard rule 4 — CSS Cascade 5: "for normal rules the declaration whose cascade layer is last wins"; unlayered declarations form an implicit final layer and "take precedence… even though the unlayered styles have a lower specificity." <https://www.w3.org/TR/css-cascade-5/#layering>
- code-standard rule 10 — WHATWG rendering, presentational hints: `align` on a `div` "is expected to center text"; the hints are attribute-keyed UA rules at zero specificity, which is why an unknown element carrying the attribute gets them too. <https://html.spec.whatwg.org/multipage/rendering.html#presentational-hints>
- code-standard rule 16 — MDN `color-scheme`: the UA changes the canvas, scrollbar and form-control defaults; "component authors must use the `prefers-color-scheme` media feature… on the rest of the elements." <https://developer.mozilla.org/en-US/docs/Web/CSS/color-scheme>
- code-standard rule 17 — WHATWG: the `hidden` attribute "is typically implemented using CSS… a rule that applies `display: block` to all elements will cancel the effects of the Hidden state." <https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute>
- code-standard rule 20 — GOV.UK service manual: "make your page work with HTML first… The JavaScript layer is not fault-tolerant." <https://www.gov.uk/service-manual/technology/using-progressive-enhancement>
- code-standard rule 8 — MDN: `<details name>` groups disclosures so "only one… can be open at a time"; `<dialog>` with `showModal()` makes the rest of the page inert and paints `::backdrop`; the Popover API (Baseline 2025) has light dismiss built in. <https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/details>, <https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog>, <https://developer.mozilla.org/en-US/docs/Web/API/Popover_API>
- code-standard rules 3, 11 — Every Layout: "A primitive is something without its own meaning or purpose as such, but which can be used in composition to make something meaningful." <https://every-layout.dev/rudiments/composition/>. CUBE CSS composition: layout systems that "support as many variants of content as possible" and provide no visual treatment. <https://cube.fyi/composition.html>
- code-standard rule 22 — Primer: base tokens map to raw values, functional tokens "represent global UI patterns", component tokens "should only be used in component CSS" — the three-tier model where components bind to the middle tier. <https://primer.style/product/primitives/token-names/>. DTCG Format Module: a token is "at minimum a name/value pair"; aliases resolve to the target's `$value`. <https://www.designtokens.org/tr/drafts/format/>
- code-standard rule 27 — Google style guide: "Never describe the code. Assume the person reading the code knows [the language] better than you do." <https://google.github.io/styleguide/pyguide.html#385-block-and-inline-comments>

**Not yet rules** (no run here has tested them; each would need an incident to enter):

- **A build step that fails says why; a step that swallows its output cannot.** A bundler run behind `--quiet` and a redirect to `/dev/null` reported a syntax error as an empty result for three runs; with output restored it named the file and column. Distinct from code-standard rule 30: that is a check that finds nothing, this a check that never ran. A candidate until a second run confirms it.
- **A lookup that cannot compute an answer returns a failure, not an empty value the caller reads as success.** A resolver returning `undefined` for one spelling of a value, to a caller treating `undefined` as nothing to assert, hid sixty-one translucent colours and every gradient. A candidate until a second run confirms it.
- **During a framework migration, the old style base lives in a cascade layer and the new one stays unlayered.** An element selector can outrank a component class (`input:not([type=…])` five times is (0,5,1)); `@layer legacy` for the old base settles it whatever the specificity, and `all: revert-layer` on the component reverts to user-agent styles, which is worse. Outside a migration code-standard rule 4 holds. A candidate until a second run confirms it.
- **A green check is evidence about what it checks; a claim of done is about the whole.** Before saying done, name what the check did not cover and close it or say so, and look at anything a person looks at. code-standard rules 33, 37 and 56 cover parity's instances. A candidate until a second run confirms it.

- Nathan Curtis, *Analysis of Variants* and *Component Contracts and Schemas* (commentary): a component spec should be **deterministic** (regenerate with nothing changed, diff is empty) and **normalised** (the default stated once, variants as deltas). One project adopted the first — a snapshot keeps its stamp when its content hash has not moved — as hygiene rather than from an incident, and deferred the second because its only benefit there was readable diffs. <https://nathanacurtis.substack.com/p/analysis-of-variants-9e440c30b93e>, <https://nathanacurtis.substack.com/p/component-contracts-and-schemas> His later argument for why the spec matters at all — inference regenerates nothing and so cannot diff, and "keep design and code in sync forever" is a lifecycle problem, not a one-shot one — is the rationale this loop was built on, stated after the fact; it admits no rule. <https://www.linkedin.com/posts/nathanacurtis_this-evening-opus-helped-me-adversarially-share-7496368573745889281-zPkq/>

- **An envelope's success flag is read before its payload, or an outage reads as an answer.** A tool returning `{ok, result}` was queried by a series of scripts that printed `result` without checking `ok`. The service was up and the *target* was gone — a Figma file had been closed — so every call returned `{ok: false, result: null}` and every script reported an empty list. Three findings were stated to the maintainer as fact: "no component name contains a slash", "zero components are prefixed", "nothing found". All three were the probe being dead, and each read as a clean result because *nothing found* and *nothing asked* have the same shape. It is the parity loop's "a probe that returns nothing is a finding about the probe", one layer up: there the selector matched no element, here the whole call failed. The candidate rule: **a caller that reads a shaped envelope asserts the success flag and fails loudly on absence — an empty payload is never data** — and a query whose answer is "none" proves the query ran before reporting it. One run, so not a rule; a second tool whose emptiness has two causes is the admission.
- **A localhost service is reachable by every page the user visits.** One project's local dashboard exposed `POST /exec`, which ran arbitrary Figma plugin code, with no `Origin` check — and a cross-site POST carrying `Content-Type: text/plain` is a CORS *simple* request, so it needs no preflight and asks no consent. The attacker cannot read the reply and does not need to: running the code is the whole attack, and the same reasoning reaches every write route. Binding to `127.0.0.1` does not help, because the attacker's code runs in the victim's browser. The file's own comment said it "has no business being reachable from the network", which was the intent and not the behaviour. The candidate rule: a service on localhost checks `Origin` against its own, on the socket upgrade as well as on HTTP, and treats an absent `Origin` as same-origin only for `GET`. One run, so not a rule — a second local tool is the admission.

- **A caller-supplied path walked into an object writes through `__proto__`.** The same service accepted `{path: "rows.abc", value}` and walked it with `node[k] = node[k] || {}`; `__proto__.x` then wrote onto `Object.prototype` for the life of the process, and the write was serialised into the record on the next save. Found by review, not by a failure — nothing misbehaves until something later reads a property it never set. The candidate rule: reject `__proto__`, `constructor`, `prototype` and empty segments before walking, or address the target by an allowlist of paths rather than by string.

- WCAG 2.2 1.4.10 Reflow at 320 CSS pixels without two-dimensional scrolling. One project's nav bar failed it and was fixed — that is one run, so this is the nearest candidate to admission; it wants a second before it becomes a rule about *how* (wrap the bar, step the padding down) rather than *that*.
- WCAG 2.2 1.4.11 Non-text Contrast (3:1 for UI components and focus rings), 2.4.11 Focus Not Obscured (sticky headers must not cover the focused control), 2.5.8 Target Size (24 × 24). All three were checked clean in one project; none has failed yet, so none has a rule.
- **`opacity` on a text container is invisible to a contrast check.** One project dimmed a completed row with `opacity: .55`, which composited its body text to **1.98:1** against the row's own tint while every declared colour still measured 8.5:1 — the tokens were right and the rendering was not. A checker that reads declared values cannot see it, and the author cannot either, since the palette it audits is unchanged. Caught by compositing the alpha against the actual backdrop rather than by any tool. The candidate rule: signal a state with a border, fill or mark, never by dimming text; where a container must be dimmed, measure the composited result. One run, so not a rule. *Resolved in part, 2026-10-02:* both projects now dim, but only for disabled, which WCAG 1.4.3 exempts from contrast — that half is code-standard rule 62 (the dim is the host's, once). A second project dimming a state that is **not** exempt is still the admission for the rest.
- WCAG 2.2 4.1.3 Status Messages — `aria-live="polite"` on a persistent node, `aria-busy` during a fetch. Checked clean in one project; code-standard rule 14 covers the half that did fail.
- CSS logical properties (`inline-size`, `margin-inline`, `inset-inline-end`) so a writing-mode change renders as intended. One project uses them throughout by habit; no incident has tested the reason.
- `prefers-reduced-motion`: reduce non-essential motion rather than delete it. One project honours it globally in its reset; untested by an incident.
- Andy Bell: "Be the browser's mentor, not its micromanager." The stance behind code-standard rules 8 and 28, cited as a stance. <https://buildexcellentwebsit.es/>

- **The product stays on the system** — a gate over page templates: no inline style, no class but the utilities, no bare control the system has a component for, no raw colour or length. Admitted from research (Shopify: 14% of its admin off Polaris a year after adoption, with a dashboard watching), not from a run: one project carries it and it has fired on nothing there yet.
- **A screenshot diff against the last kept set**, advisory, for paint order and overlap no property comparison sees. From Chromatic's baseline model; untested against a real regression so far.
- **A gate may not rest on today's content volume.** One project's screen check declares "the page at its end", which only scrolls while the live feed is taller than the design frame; enough items expiring from the feed would make the page fit, the difference vanish, and the run fail on a now-stale waiver with no code change. Latent, not yet fired.

*(added 2026-09-16, from one project's front-end audit — each has one run and stays here until a second)*

- **A layer's `> *` beats a component's root, so a child that hugs says so through a knob.** A page row said `> * { flex: 1 }` in the screens layer; the component that must not grow said `flex: none` on its root in the components layer and lost, whatever its specificity. The row reads `var(--ds-row-flex, 1)` and the component sets the property — the same shape as code-standard rule 38, in the other direction.
- **A gate that bans styling a component's parts must also ban its root.** One project's page-rule gate matched `.ds-x .ds-y__part` and let `.ds-x > .ds-y { flex: none }` through in five sheets; the compiled-selector version named twelve.
- **An exemption that matches nothing is a finding.** Four waivers and one override in one project's parity tables named layers a snapshot no longer drew; nothing reported them, and the prose beside them described a margin the code had stopped setting.
- **A skip is only for want of input, and names the probe.** A driven-path suite skipped "no project with a role" because its probe looked for a select the dialog no longer rendered; the rebuilt thing passed by not running. A skip states what it looked for; anything else is a failure.
- **A wait names what it waited for and ends.** `until curl …; do sleep 1; done` held a run for ever with nothing printed; a bounded wait naming the server and the seconds turned the same hang into one line.
- **A cleanup kills what listens, not the PID it launched.** `pnpm exec next dev` is three processes deep; killing the first left a server on the port that made the next gate refuse to start. Kill by port at the end.
- **Anything that runs the app outside production pins the mailer.** A local maintenance run inherited `.env.local` and would have mailed; the harness sets the console provider and clears every redirect before starting anything.
- **Copies of a fixture are a fork.** Nine stories files carried the same navigation fixture and twelve parity tables the same six shell layers; one copy was two layers short and nobody could see which. One module, imported.
- **A client component receives words, not the dictionary.** Four client files imported the translation maker and its whole table into the bundle to read three labels; the labels seam (`labels?: Partial<typeof EN>`) is the pattern the other components already had.
- **A composite ARIA role ships with its keyboard or not at all.** A `role="menu"` with `menuitemradio` children answered no arrow key; the roving-focus handler already existed in the tabs and was lifted into a hook.
- **`aria-live` on an element that mounts with its content announces nothing.** Five field messages carried `live` and were never read; the described-by relation already carried the text on focus.
- **Unused symbols are errors and dictionary keys are referenced or deleted.** 131 unused translation keys and 43 lint warnings nobody read; a warning is a queue nobody drains.
- **A dashed INSIDE stroke is an outline drawn inside the edge, not a border.** Figma's INSIDE stroke with strokes-in-layout off takes no room, and an inset box-shadow (the house translation) cannot be dashed; `outline: <w> dashed <colour>; outline-offset: -<w>` is the same paint at the same place. The parity probe already reads that outline as the inner ring and measures it, but the adapter still asserts `border-*-style: dashed`, so the project waives the border (one project's photo upload, 20 Oct 2026). Candidate for the adapter: read a dashed INSIDE stroke's style from the outline.
- **A secret has one home, and everything that needs it reads that home or is written by the one command that renews it.** A copy typed by hand into a second place outlives the key it copied. A project's Anthropic key was renewed on the laptop on 2026-10-23, the old one was revoked, and the server's own copy in its host config went on being refused (401) for five days; no brief was written, and the refusals sat in a log. Fixed by `bin/set-key`: keys in one folder outside the repo, one file each, `keys.conf` naming who else hears about each one, and a server config made to read the key from a file the same command writes over `ssh` (since 2026-10-31 a `run` hand-on in the machine's `keys.conf`, not the toolkit's code) — its first real run refused, rightly, to choose between a live config and an `_old` copy of the site. One run, so not a rule; a second project whose renewed key misses a copy is the admission.
